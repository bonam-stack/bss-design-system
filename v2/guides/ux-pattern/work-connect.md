각각 분절된 업무를 잇는 두 기능을 규정합니다.
묶어서 진행할 업무는 Task Flow로, 흐름 밖의 업무는 Cross-linking으로 잇습니다.

#### 개요 · 언제 쓰나요?

업무를 [편성 단위](work-composition.html)대로 자르고 나면 사용자는 여러 업무를 오가며 일하게 됩니다.
같은 조회를 반복하지 않도록 잇는 방법이 필요합니다.

###### ✓ 이럴 때 사용합니다

- 여러 업무를 순서대로 이어 상담 흐름을 만드는 경우
- 하던 업무의 조회조건·선택 값을 다른 업무로 넘겨야 하는 경우

###### ✕ 다른 패턴을 사용합니다

- 업무를 자르는 단위와 화면 유형 → [업무 화면 편성](work-composition.html)
- 한 화면 안에서 앞뒤 단계로 이어지는 업무 → [다단 구성](layout-columns.html)

#### 두 기능 한눈에 보기

|  | Task Flow | Cross-linking |
| --- | --- | --- |
| 성격 | 하나의 처리를 위해 **미리 짜 둔 업무 흐름** | 필요할 때 **따로 여는 업무 하나** |
| 누가 여나 | 시스템이 편성해 제공합니다 | 사용자가 골라서 엽니다 |
| 순서 | 있습니다 | 없습니다 |
| 완료한 뒤 | 완료 업무도 흐름에 남습니다 | 완료 업무도 남고, 영향받은 다른 업무에 갱신이 표기됩니다 |
| GNB 에서의 위치 | 앞쪽, 편성한 순서대로 | Task Flow 뒤 |
| 여는 곳 | Communicator 추천 · 사이드 내비게이션 바 메뉴 검색 | 화면 안의 이동 버튼 및 링크 |

둘 중 하나를 고르는 것이 아니라 함께 씁니다.
Task Flow가 짜 준 흐름 안에서도 그 흐름에 없는 업무로 옮길 때 Cross-linking을 씁니다.

#### Task Flow · 업무 오케스트레이션

하나의 처리를 위해 필요한 업무를 미리 짜서 GNB에 순서대로 제공합니다.

##### 흐름을 만드는 방식

- **Static**: 사전에 정의한 흐름을 그대로 제공합니다. (예. 요금제 변경 → 청구 정보 조회 → 상담 후 처리)
- **AI-driven**: 고객 데이터와 상담 맥락을 분석해 업무 조합을 추천합니다.

##### 진행 규칙

- **화면 유형은 섞일 수 있습니다**: 유형은 업무마다 고릅니다.
- **Auto-Routing**: 진행 중인 업무를 완료하면 그 탭을 닫고 다음 업무를 엽니다. 이미 편성된 업무 사이의 진행이며, 새 업무를 만들지 않습니다.

#### Cross-linking · 업무 간 데이터 연결

Task Flow 밖의 업무를 열어도 데이터가 그대로 이어지게 하는 연결 방식입니다.
진입은 라벨 끝에 이동 아이콘을 단 버튼이나 링크로 합니다.
**‘업무명 ↗’** 형식이며, 이렇게 생긴 것은 모두 Cross-linking 입니다.

##### 넘기는 값

- **조회조건과 고른 항목을 넘깁니다**: 새로 연 업무의 입력·조회 모듈에 자동으로 채웁니다.
- **값은 받는 업무의 조회조건이 같은 형태일 때 이어집니다**: 같은 업무 대상을 쓰는 업무끼리 조회조건 형태를 맞추는 기준은 [조회조건 모듈](search-conditions.html#consistency)이 규정합니다.
- **권한을 실시간으로 검증합니다**: 권한이 없는 업무도 감추지 않고 비활성으로 둡니다. 감추면 그 업무가 있다는 것도, 왜 열 수 없는지도 알 수 없습니다. 표기는 [권한 제한 처리](resp-permission.html)가, 진입한 뒤 막히는 경우는 [오류처리](node-flow-fail.html)가 규정합니다.

##### 나가기 전의 확인

- **작성 중인 내용을 두고 나가는 이동은 모두 묻습니다**: 어떤 이동은 묻고 어떤 이동은 묻지 않으면, 다이얼로그가 「중요해서 묻는 것」으로 읽히지 않고 습관적으로 넘기게 됩니다.
- **확인을 받은 뒤에 넘깁니다**: 다이얼로그 규격은 [확인·경고 다이얼로그](resp-dialog.html)가 규정합니다.

#### 업무 탭

열린 업무는 GNB에 탭으로 나타납니다.
여기서는 두 기능의 탭이 무엇이 다른지만 정하고, 색·표기·닫기와 주 업무세션 규격은 [GNB](layout-gnb.html)가 규정합니다.

- **자리**: Cross-linking 탭은 Task Flow 탭들 뒤에 붙입니다.
- **수명**: 완료했다고 시스템이 탭을 지우지 않습니다. 닫을지는 사용자가 정합니다.
- **갱신**: 처리 결과가 다른 업무에 영향을 미치면 그 탭에 갱신을 표기해 다시 확인하게 합니다.
- **갱신을 알립니다**: 탭 표기와 함께 토스트로 변경이 있었다는 사실을 알립니다. 다른 업무를 보고 있으면 탭 표기만으로는 알아채기 어렵습니다. 반드시 확인해야 하는 안내는 아니므로 가볍게 알리고 사라지게 합니다. 규격은 [토스트·스낵바](resp-toast.html)가 규정합니다.

#### Do / Don't

###### Do · 이렇게 합니다

- 묶어서 진행할 업무는 Task Flow로, 흐름 밖의 업무는 Cross-linking으로 잇습니다.
- 새로 연 업무에는 하던 업무의 조회조건과 고른 항목을 넘깁니다.
- 작성 중인 내용이 있으면 나가기 전에 확인을 받습니다.

###### Don't · 이건 피합니다

- Task Flow와 Cross-linking을 둘 중 하나만 고르는 것으로 다루지 않습니다.
- Cross-linking으로 연 업무를 Task Flow 흐름 안에 끼워 넣지 않습니다.
- 완료했다는 이유로 탭을 시스템이 지우지 않습니다.
- 권한이 없다는 이유로 업무를 목록에서 감추지 않습니다.
