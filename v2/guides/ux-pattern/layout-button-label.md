버튼에 무엇이라 쓰고 어떤 아이콘을 붙이는지 정의합니다.
화면 유형과 상관없이 일반 UI·노드 UI에 같게 적용하는 공통 표준입니다.

#### 개요 · 언제 쓰나요?

버튼에 무엇이라 쓰고 어떤 아이콘을 붙이는지 정의합니다.
버튼을 어디에 놓는지는 화면 유형에 따라 갈리지만, 명칭과 아이콘은 유형과 상관없이 같게 적용합니다.

###### ✓ 이럴 때 사용합니다

- 버튼 라벨 문구를 정하거나 화면마다 다른 표현을 통일할 때
- 라벨 옆에 아이콘을 붙일지, 어떤 아이콘을 쓸지 정할 때
- 텍스트 링크 등 버튼이 아닌 인터랙션 요소의 표기를 정할 때

###### ✕ 다른 문서를 따릅니다

- 버튼을 어디에 놓는지 → [버튼 구조 및 동작](layout-action.html)
- 버튼의 유형·상태 등 컴포넌트 시각 규격 → 컴포넌트 가이드(Button)

#### 라벨

핵심 원칙버튼 라벨은 사용자 액션의 의미를 전달하는 명사형 핵심 단어로 쓰고, 아래 표현을 권장합니다.
화면이 달라도 같은 동작에는 같은 라벨을 쓰는 것을 권장합니다.

- **일반 UI·노드 UI 공통**: 표준 명칭·라벨은 화면 유형과 상관없이 같게 적용합니다.
- **타 업무 페이지 링크는 호칭을 통일합니다**: 다른 업무 화면으로 가는 링크를 표기할 때 그 업무·페이지의 호칭을 화면마다 다르게 쓰지 않고 동일하게 맞춥니다.
- **업무·기술 용어는 사내 공용어를 씁니다**: 특정 업무나 기술 용어를 표기할 때는 가급적 사내에서 통용되는 공용어를 사용합니다.
- **대상을 앞에 붙일 수 있습니다**: 무엇에 대한 동작인지 분명히 할 때 대상을 앞에 붙입니다. (예. 표준 명칭 삭제 → ‘선택 항목 삭제’)
- **‘~하기’ 형태는 권장하지 않습니다**: ‘저장하기’처럼 ‘~하기’로 끝나는 라벨 대신 표준 명칭(‘저장’)을 씁니다.

주소는 통상 쓰는 말에 맞춰 ‘변경’을 우선합니다.

##### 노드 CTA 라벨

노드 블록 하단 CTA와 액션바 주 버튼에 쓰는 라벨입니다.
노드 흐름은 ‘다음 →’으로 단계를 이어 가다가 마지막 노드에서 ‘완료 ✓’로 끝나는 것이 표준입니다.

핵심 원칙라벨은 버튼이 하는 일로 정하고, 아이콘은 누른 뒤 다음 노드가 있는지로 정합니다.
단계만 넘기면 ‘다음’·‘완료’를 쓰고, 업무 행위를 실행하면 그 행위를 나타내는 명사형 라벨을 씁니다.

| 버튼이 하는 일 | 다음 노드가 있음 (→) | 마지막 노드 (✓) |
|---|---|---|
| 진행 | 다음 | 완료 |
| 실행 | 행위 라벨 (예. 선택 · 고객 인증) | 행위 라벨 (예. 결제) |

- **진행은 ‘다음’입니다**: 정보를 읽고 인지한 뒤 다음 노드로 넘어가는 버튼은 ‘다음’을 씁니다. 흐름 중간에서 ‘확인’으로 마무리하지 않습니다.
- **‘완료’는 마지막 노드에만 씁니다**: 흐름 중간의 라벨에 ‘완료’를 넣지 않습니다. (예. ‘선택 완료’ → ‘선택’)
- **실행은 행위를 라벨로 씁니다**: 값을 확정하거나 인증·결제처럼 업무 행위를 실행하는 버튼은 ‘다음’·‘완료’ 대신 그 행위를 나타내는 명사형 라벨을 씁니다.
- **행위 라벨은 표준 명칭을 먼저 씁니다**: 위 표준 명칭에 있는 말을 먼저 쓰고, 무엇에 대한 행위인지 대상을 앞에 붙입니다. (예. 인증 → ‘고객 인증’ · ‘공공 마이데이터 인증’)
- **실행 라벨에도 다음 노드가 있으면 `→`를 붙입니다**: 다음 노드가 있으면 `→`, 마지막 노드면 `✓`를 붙입니다.
- **한 번 눌러 실행하고 이어서 진행합니다**: 실행에 성공하면 바로 다음 노드로 넘어갑니다. 실행 버튼과 ‘다음’을 한 노드에 함께 두지 않습니다. 실행에 실패하면 노드에 머무르고, 인라인 오류와 ‘다시 시도’를 보여 줍니다.
- **액션바도 같은 라벨입니다**: 액션바의 주 버튼은 노드 하단 CTA와 같은 라벨·같은 아이콘을 씁니다.

| 라벨 | 구분 | 의미 | 사용하지 않는 말 |
|---|---|---|---|
| 다음 | 진행 | 지금 단계를 확정하고 다음 노드로 진행 | 넘어가기 · Next · 확인 |
| 완료 | 진행 | 노드 흐름의 마지막 단계를 끝내고 업무 결과를 확정 |  |
| 선택 | 실행 | 고른 값을 확정 | 선택 완료 |
| 저장 | 실행 | 입력한 값을 저장 |  |
| 요청 전송 | 실행 | 고객·외부에 요청을 보내고 응답을 기다림 |  |
| 동의 | 실행 | 고지한 내용에 동의를 받아 확정 | 승인 |
| 발송 | 실행 | SMS·LMS 등 메시지를 보냄 | 보내기 |
| 고객 인증 | 실행 | 고객 본인을 확인 (예. 공공 마이데이터 인증) |  |
| 검증 실행 | 실행 | 입력·선택한 값의 유효성을 시스템으로 검증 |  |
| 결제 | 실행 | 요금·대금 결제를 실행 |  |
| 다시 시도 | 실행 | 실패한 처리를 같은 조건으로 재실행 | 재시도 · Retry |

##### 노드 CTA 특수 기능 라벨

노드 흐름을 넘어 업무 페이지 전체에 영향을 주는 라벨입니다.
아래 목록에 있는 라벨만 쓰고, 화면마다 새로 만들지 않습니다.

| 라벨 | 의미 | 아이콘 |
|---|---|---|
| 상담 종료 | 모든 상담 프로세스를 마치고 고객과의 통화를 끊은 뒤 업무 페이지 전체를 완료 처리 | ✓ |

기억할 점‘완료’와 ‘상담 종료’는 끝내는 범위가 다릅니다.
‘완료’는 지금 노드 흐름(업무 하나)을 끝내고, ‘상담 종료’는 상담 전체와 업무 페이지를 끝냅니다.

어느 노드 블록이 어떤 라벨을 쓰는지는 [버튼 구조 및 동작](layout-action.html)의 노드 UI 탭이 정리합니다.

#### 아이콘

핵심 원칙버튼 아이콘은 그 버튼의 동작이 아니라, 눌렀을 때 이어지는 UI 반응(사이드 패널·팝업·다음 단계 등)을 예고합니다.
라벨과 함께 붙으며, 같은 라벨이라도 이어지는 UI가 다르면 아이콘이 달라집니다.

- **이어지는 UI를 예고합니다**: 사이드 패널·팝업·이동형 창·브라우저 새 창·다음 노드 등 무엇이 열리거나 어디로 가는지를 라벨 옆 아이콘으로 미리 알립니다.
- **아이콘은 라벨 왼쪽이 원칙**: 아이콘은 라벨 왼쪽에 붙입니다.
- **나가는 방향은 오른쪽입니다**: 페이지를 전환하거나 다음 노드로 넘어가는 `→`와 새 업무를 여는 `↗`는 라벨 오른쪽에 둡니다. 지금 자리를 떠나 어디로 향한다는 메타포이기 때문입니다.
- **노드 하단 CTA는 모두 오른쪽입니다**: 노드 블록의 하단 CTA는 아이콘 종류와 상관없이 라벨 오른쪽에 둡니다. 폭이 넓고 가운데 정렬이라 아이콘이 뒤에 붙어야 균형이 맞습니다. 같은 노드 안이라도 사이드 패널을 여는 보조 버튼 등은 왼쪽 원칙을 그대로 따릅니다.
- **라벨과 함께 씁니다**: 아이콘은 라벨에 곁들이는 것이 기본입니다. 라벨 없이 아이콘만 두는 여섯은 아래 아이콘만 쓰는 경우에서 다룹니다.
- **기능 아이콘은 별개**: 이어지는 UI가 아니라 기능 자체를 나타내는 아이콘도 있습니다. → 아래 기능 아이콘
- **버튼에만 한정하지 않습니다**: 텍스트 링크·정보 요약의 링크 행·검색 필드 옆 등 다른 인터랙션 요소에도 같은 아이콘 규정을 적용합니다. 다만 붙는 자리에 따라 아이콘 위치가 달라집니다. (아래 사이드 패널 절 참고)
- **남용하지 않습니다**: 이어지는 방식이나 기능이 분명한 버튼에만 쓰고, 장식용 아이콘은 두지 않습니다.

##### 라벨과 함께 붙는 아이콘

아이콘 규정은 화면 유형과 상관없이 공통입니다.
다만 몇 가지는 노드 UI에서만 상황이 생겨 실제로는 그쪽에서만 쓰입니다.

| 아이콘 | 이름 | 예고하는 것 | 자리 | 적용 |
|---|---|---|---|---|
|  | 사이드 패널 | 우측에서 사이드 패널이 슬라이드로 열림 (예. 옵션 변경 · 메시지 변경 · 이력 확인) | 라벨 왼쪽 (예외 아래) | 공통 |
|  | 팝업 | 팝업이 열림 (예. 상세보기 · 미리보기) | 라벨 왼쪽 | 공통 |
|  | 풀페이지 팝업 | 전체 화면 팝업이 열림 | 라벨 왼쪽 | 공통 |
|  | 유틸리티 팝업 | 보조 도구 팝업이 열림 | 라벨 왼쪽 | 공통 |
|  | 브라우저 팝업 | 레이어가 아니라 브라우저가 별도 창을 띄움 | 라벨 왼쪽 | 공통 |
|  | 이동 | 일반 UI: 상세 화면으로 페이지 전환 ([전체 화면 전환](view-transitions.html)) · 노드 UI: 지금 단계를 확정하고 다음 노드로 진행 (예. 다음 · 선택 · 고객 인증) | 라벨 오른쪽 | 공통 |
|  | 확정 | 노드 흐름을 끝내고 더 진행하지 않음 (예. 완료 · 결제 · 상담 종료) | 라벨 오른쪽 | 노드 UI |
|  | 새 업무 생성 | 후속 업무를 만들어 그 화면으로 이동 (예. 완결형의 다음 조치) | 라벨 오른쪽 | 공통 |

아래는 실제 버튼에 붙은 모습입니다.
여는 방식·노드 CTA·기능 세 줄로 나뉘며, 각 줄이 그 맥락의 아이콘 자리를 그대로 보여 줍니다.

유의사항자리는 아이콘이 아니라 버튼의 종류가 정합니다.
노드 하단 CTA는 어떤 아이콘이든 라벨 오른쪽에 두고, 그 밖의 버튼은 위 표의 자리를 따릅니다.
그래서 같은 팝업 아이콘이라도 일반 UI의 ‘상세보기’는 왼쪽, 노드 CTA의 ‘미리보기’는 오른쪽입니다.

기억할 점`→`의 뜻은 화면 유형에 따라 갈립니다.
일반 UI에서는 상세 화면으로 페이지를 전환하고, 노드 UI에서는 다음 노드로 진행합니다.
노드 UI에서 `→`와 `✓`는 짝으로 갈립니다.
누른 뒤 다음 노드로 넘어가면 `→`, 노드 흐름이 끝나면 `✓`를 씁니다.
라벨이 ‘다음’이든 행위 라벨이든 같은 기준입니다.

##### 기능 아이콘

이어지는 UI가 아니라 기능 자체를 나타내는 아이콘입니다.
모두 라벨 왼쪽에 붙고 화면 유형과 상관없이 공통으로 씁니다.

| 아이콘 | 이름 | 무엇을 하나 |
|---|---|---|
|  | 저장 | 입력·수정한 데이터를 저장 |
|  | 다운로드 | 데이터를 로컬 PC로 내려받기 (예. 엑셀 다운로드) |
|  | 업로드 | 로컬 파일을 시스템에 올리기 (예. 엑셀 업로드) |
|  | 인쇄 | 화면·문서를 인쇄 |
|  | 검색 | 입력한 조건으로 조회 (예. 조회 · 상세조회) |
|  | 버튼 그룹 | 접어 둔 비필수 버튼을 눌러서 펼쳐 보임 (예. 관련 기능) |

버튼 그룹 아이콘은 그룹을 여는 버튼에만 붙이고, 펼쳐진 목록 안의 개별 항목에는 붙이지 않습니다.
무엇을 그룹으로 묶고 어디에 두는지는 [버튼 구조 및 동작](layout-action.html)의 버튼 그룹 절이 정합니다.

##### 아이콘만 쓰는 경우

라벨 없이 아이콘만 두는 버튼입니다.
뜻이 보편적이고 화면마다 반복되는 기능에 한정하며, 접근성을 위해 대체 텍스트를 둡니다.

| 아이콘 | 뜻 | 쓰는 곳 |
|---|---|---|
| › | 더보기 | 목록·요약 끝에서 현재 페이지를 유지한 채 데이터를 이어 노출 |
| + | 추가 | 테이블 행이나 입력 영역을 한 줄 더 켜기 |
| ↻ | 초기화 | 조회조건·검색 영역에서 입력한 조건을 기본 상태로 되돌리기 |
| × | 닫기 | 팝업·모달 헤더 우측에서 종료 |
|  | 다운로드 | 내려받을 대상이 자리로 분명할 때 그 데이터를 로컬 PC로 내려받기 (예. 첨부 파일 옆) |
|  | 업로드 | 올릴 자리가 분명할 때 로컬 파일을 시스템에 올리기 (예. 파일 첨부 영역) |

이 여섯을 벗어나는 기능에는 아이콘만 두지 않고 라벨을 함께 답니다.

##### 사이드 패널 아이콘의 예외

사이드 패널 아이콘은 버튼 라벨 왼쪽에만 오지 않습니다.
패널을 여는 자리면 어디든 같은 아이콘으로 예고하며, 그때는 자리 규칙이 달라집니다.

| 붙는 자리 | 아이콘 위치 | 무엇을 여나 |
|---|---|---|
| 버튼 | 라벨 왼쪽 | 옵션 변경 · 메시지 변경 등 패널에서 처리하는 동작 |
| 정보 요약의 링크 행 | 항목명 오른쪽 | 그 항목의 상세를 패널로 열람 (값은 바꾸지 않음) |
| 검색 필드 옆 | 필드 오른쪽에 아이콘 단독 버튼 | 목록이 많아 펼치기 어려울 때 패널에서 찾아 지정 |

기억할 점자리가 달라도 뜻은 하나입니다.
이 아이콘이 보이면 우측에서 패널이 열린다는 뜻이며, 팝업이나 페이지 이동에는 쓰지 않습니다.

#### Do / Don't

###### Do · 이렇게 합니다

- 표준 명칭으로 라벨을 통일하고, 같은 동작에는 같은 명칭을 씁니다.
- 무엇에 대한 동작인지 분명히 할 때 대상을 앞에 붙입니다.
- 아이콘은 이어지는 UI 반응을 라벨과 함께 예고하는 선에서 씁니다.
- 다음 노드로 넘어가는 버튼에는 `→`를, 노드 흐름을 끝내는 버튼에는 `✓`를 붙입니다.
- 브라우저가 별도 창을 띄우는 버튼에는 브라우저 팝업 아이콘을 붙여 창이 분리된다는 것을 미리 알립니다.
- 접어 둔 버튼을 펼치는 버튼에는 버튼 그룹 아이콘을 붙입니다.
- 노드 하단 CTA는 아이콘 종류와 상관없이 라벨 오른쪽에 둡니다.
- 아이콘 단독으로 쓸 때는 접근성을 위해 대체 텍스트를 둡니다.

###### Don't · 이건 피합니다

- ‘중복검사’·‘내려받기’·‘저장하기’처럼 사용하지 않는 말을 라벨로 쓰지 않습니다.
- 같은 동작을 화면마다 다른 라벨로 쓰지 않습니다.
- 같은 대상을 바꾸는 버튼에 ‘수정’과 ‘변경’을 섞어 쓰지 않습니다.
- 노드 흐름 중간의 CTA에 ‘완료’를 넣거나 ‘확인’으로 마무리하지 않습니다.
- 특수 기능 라벨 목록에 없는 라벨로 업무 페이지 전체를 끝내지 않습니다.
- 아이콘을 버튼의 동작 표식으로 쓰거나 장식용으로 붙이지 않습니다.
- 레이어로 열리는 팝업에 브라우저 팝업 아이콘을 쓰지 않습니다.
- 뜻이 보편적이지 않은 기능에 아이콘만 두고 라벨을 생략하지 않습니다.
