화면의 데이터나 첨부 파일을 로컬 PC로 내려받는 표준 기능 패턴입니다.
받기 전에 거치는 관문(권한 · 마스킹 · 사유 · 비밀번호)과 받는 방식(즉시형 · 요청형)을 규정합니다.

#### 개요 · 언제 쓰나요?

고객 정보가 담긴 파일은 누르는 즉시 받을 수 없는 경우가 많습니다.
권한을 확인하고, 다운로드 사유를 남기고, 마스킹을 해제하려면 승인을 받아야 합니다.
파일이 크거나 승인이 필요하면 지금 받지 못하고, 준비된 뒤에 받습니다.

이 문서는 이런 경우를 하나의 흐름으로 정리합니다.
다운로드는 받기 전 관문을 거친 뒤 즉시형이나 요청형 중 한 방식으로 파일을 받습니다.
관문이 몇 개 걸리든, 어느 방식으로 받든 같은 규칙을 따릅니다.

###### ✓ 이럴 때 사용합니다

- 테이블의 데이터를 엑셀 등 파일로 내보내는 경우
- 저장된 첨부 파일을 내려받는 경우
- 다운로드에 권한 · 사유 · 승인 · 비밀번호가 필요한 경우
- 파일을 만드는 데 시간이 걸려 나중에 받아야 하는 경우

###### ✕ 다른 패턴을 사용합니다

- 파일을 올리는 경우 → [파일 업로드하기](form-file-upload.html) · [엑셀 업로드하기](grid-excel-upload.html)
- 다운로드 버튼의 라벨과 아이콘 → [버튼 라벨 · 아이콘](layout-button-label.html)

핵심 원칙1. 관문은 파일의 종류가 아니라 파일에 담긴 정보에 따라 정합니다.
2. 권한이 없으면 누르기 전에 보여 줍니다.
3. 걸리는 관문은 다운로드 설정 팝업 하나에 모아 한 번에 묻습니다.
4. 지금 받을 수 없는 파일은 요청형으로 받습니다. 요청한 뒤에는 하던 업무를 이어 가고, 준비되면 알림에서 받습니다.

#### 구성요소

1. 다운로드 버튼액션 영역이나 첨부 파일 옆에 둡니다. 라벨과 아이콘은 [버튼 라벨 · 아이콘](layout-button-label.html)을 따릅니다.
2. 다운로드 설정 팝업걸리는 관문을 한 번에 묻습니다. 관문이 하나도 걸리지 않으면 열지 않습니다.
3. 요청 안내요청형으로 받을 때 요청을 접수했다고 알리는 Snackbar입니다.
4. 알림 항목요청한 파일의 상태를 보여 주고, 준비되면 그 자리에서 받게 합니다. 사이드 내비게이션 바 알림에 쌓입니다. 알림 항목의 구성은 가안입니다: [요청형의 상태와 알림](#request)과 함께 확정합니다.

#### 핵심 동작 · 상태

##### 다운로드 대상

다운로드 대상은 두 가지입니다.
어느 관문이 걸리는지는 대상이 아니라 담긴 정보로 정합니다.

| 관문 | 데이터 내보내기 (예. 테이블 엑셀 다운로드) | 첨부 파일 받기 (예. 증빙 서류) |
| --- | --- | --- |
| 권한 | 걸립니다 | 걸립니다 |
| 마스킹 | 개인정보 칼럼이 있으면 걸립니다 | 걸리지 않습니다 · 파일 안의 정보는 가릴 수 없습니다 |
| 사유 | 개인정보가 담기면 걸립니다 | 개인정보가 담긴 서류이면 걸립니다 (예. 신분증 사본) |
| 비밀번호 | 화면마다 정합니다 | 화면마다 정합니다 |

- **첨부 파일은 마스킹 대신 권한과 사유로 통제합니다**: 이미 저장된 파일의 내용은 다운로드할 때 가릴 수 없습니다.
- **DRM 암호화는 관문이 아닙니다**: 사용자의 조작 없이 저장할 때 적용됩니다. → [DRM](#drm)

##### 받기 전 관문

| 순서 | 관문 | 걸리면 |
| --- | --- | --- |
| 1 | 권한 | 버튼을 잠그고, 권한을 요청하게 합니다 |
| 2 | 마스킹 | 마스킹한 파일과 해제한 파일 중에서 고르게 합니다 |
| 3 | 사유 | 사유코드를 고르고 사유를 입력하게 합니다 |
| 4 | 비밀번호 | 파일을 열 때 쓸 비밀번호를 정하게 합니다 |

- **권한은 버튼에서, 나머지는 다운로드 설정 팝업에서 확인합니다**: 권한이 없으면 팝업을 열 이유가 없습니다.
- **관문마다 팝업을 따로 띄우지 않습니다**: 사유를 입력하고 나서 다시 비밀번호 팝업이 뜨면 몇 단계가 남았는지 알 수 없습니다.
- **관문이 하나도 걸리지 않으면 누르는 즉시 받습니다**: 팝업을 열어 확인만 받지 않습니다.

##### 권한

- **권한이 없으면 다운로드 버튼에 잠금 아이콘을 달고 비활성으로 둡니다**: 표기는 [권한 제한 처리](resp-permission.html)의 UI 요소 권한 표기를 따릅니다.
- **잠긴 버튼을 누르면 툴팁으로 권한이 없음을 알리고 ‘권한 요청’ 링크를 답니다**: 링크를 누르면 권한 요청 화면으로 이어집니다.
- **누르기 전에 알 수 없는 경우에만 누른 뒤에 알립니다**: 권한이 데이터에 따라 달라지는 경우입니다. (예. 조회 결과에 내 권한 밖의 데이터가 섞여 있음) 이때는 Snackbar로 받을 수 없는 이유를 알리고 ‘권한 요청’을 답니다.

##### 다운로드 설정 팝업

걸리는 관문만 팝업에 담고, 걸리지 않는 관문은 넣지 않습니다.

1. 대상무엇을 받는지 적습니다. (예. 파일 이름 · 건수)
2. 마스킹마스킹한 파일과 해제한 파일 중에서 고릅니다. 마스킹한 파일이 기본값입니다.
3. 사유사유코드와 상세 사유를 입력합니다.
4. 비밀번호파일을 열 때 쓸 비밀번호를 정합니다.
5. 기록 안내다운로드 이력이 기록된다는 사실을 한 줄로 알립니다.
6. 버튼즉시형은 ‘다운로드’, 요청형은 ‘다운로드 요청’입니다.

- **요청형으로 바뀌면 그 이유를 버튼 위에 적습니다**: 같은 다운로드 버튼을 눌렀는데 받는 방식이 달라지기 때문입니다. (예. 마스킹 해제는 승인이 필요해 요청으로 처리합니다)
- **입력을 마치기 전까지 버튼을 비활성으로 둡니다**: 필수 항목을 채우면 활성으로 바꿉니다.

##### 마스킹

- **마스킹한 파일을 기본으로 받습니다**: 파일도 화면과 같이 업무에 필요한 만큼만 보입니다. ([마스킹 처리](resp-masking.html))
- **파일의 마스킹 방식은 화면과 같습니다**: 항목별 마스킹 기준을 그대로 씁니다.
- **해제한 파일은 승인을 받은 뒤에 받습니다**: 해제를 고르면 요청형으로 바뀝니다.
- **화면에서 해제한 상태와 파일은 관계가 없습니다**: 화면에서 인증으로 마스킹을 해제했어도 파일은 마스킹한 채로 받습니다. 화면의 해제는 상담 중인 고객 한 명에 대한 것이고, 파일은 여러 고객의 정보를 담습니다.

##### 사유

- **사유코드는 필수로 고릅니다**: 코드 목록은 업무마다 정합니다.
- **상세 사유는 사유코드에 따라 필수가 됩니다**: 기타처럼 코드만으로 사유를 알 수 없을 때 입력하게 합니다.
- **사유는 다운로드 이력에 함께 남깁니다**

##### 비밀번호

유의사항비밀번호를 정하고 전달하는 방식은 가안입니다.
고객사의 보안 정책에 따라 바뀔 수 있습니다.

- **오피스 파일과 압축 파일에 비밀번호를 겁니다**: 주로 외부로 보낼 파일이나 DRM이 적용되지 않는 환경의 파일입니다.
- **사용자가 비밀번호를 입력합니다 (가안)**: 규칙(길이 · 조합)을 입력란 아래에 미리 보이고, 한 번 더 입력해 확인합니다.
- **비밀번호를 파일 이름이나 알림에 적지 않습니다**: 파일과 같은 경로로 전달하면 비밀번호를 건 의미가 없습니다.

##### 받는 방식

| 방식 | 언제 | 흐름 |
| --- | --- | --- |
| 즉시형 | 관문을 통과하면 바로 파일을 만들 수 있을 때 | 누르기 → (다운로드 설정) → 저장 |
| 요청형 | 파일을 만드는 데 시간이 걸릴 때 (온디맨드 배치) | 누르기 → (다운로드 설정) → 요청 → 생성 → 알림에서 받기 |
|  | 승인이 필요할 때 (마스킹 해제 · DRM 해제) | 누르기 → 다운로드 설정 → 요청 → 승인 → 생성 → 알림에서 받기 |

- **받는 방식은 사용자가 고르지 않습니다**: 건수 · 마스킹 해제 여부처럼 정해진 기준에 따라 시스템이 정합니다.
- **배치와 승인을 같은 요청형으로 다룹니다**: 사용자에게는 둘 다 지금 받지 못하고 나중에 받는 일입니다.
- **즉시형이 오래 걸리면 진행 중임을 보여 줍니다**: 파일이 저장될 때까지 다운로드 버튼에 진행 표시를 두고 다시 누를 수 없게 합니다.
- **즉시형은 받은 뒤 메시지를 띄우지 않습니다**: 브라우저가 다운로드를 표시합니다.
- **다운로드 설정 팝업 없이 요청형이 되면 그 이유를 Snackbar에 적습니다**: 관문이 없어도 건수 때문에 요청형이 될 수 있습니다. (예. 120,000건이라 파일을 만드는 데 시간이 걸립니다)

##### 요청형의 상태와 알림

유의사항이 절은 가안입니다.
[피드백 체계](msg-system.html#msg-categories)의 개인업무 메시지(가안)와 함께 확정합니다.

- **요청하면 Snackbar로 접수를 알립니다**: 준비되면 알림에서 받을 수 있다고 함께 적습니다. 사용자는 기다리지 않고 하던 업무를 이어 갑니다.
- **요청한 파일은 사이드 내비게이션 바 알림에 항목으로 쌓입니다**: 상태가 바뀌면 알림 배지로 알립니다.
- **받을 수 있게 되면 알림 항목에서 바로 받습니다**: 요청한 화면으로 돌아가지 않습니다.

| 상태 | 뜻 | 알림 항목에서 할 수 있는 일 |
| --- | --- | --- |
| 승인 대기 | 승인을 기다립니다 | 요청 취소 |
| 생성 중 | 파일을 만들고 있습니다 | 요청 취소 |
| 받을 수 있음 | 파일이 준비되었습니다 | 다운로드 |
| 반려 | 승인자가 반려했습니다 | 반려 사유 보기 |
| 실패 | 파일을 만들지 못했습니다 | 다시 요청 |
| 만료 | 보관 기간이 지났습니다 | 다시 요청 |

- **받을 수 있는 기간을 알림 항목에 적습니다**: 기간이 지나면 만료로 바뀝니다.
- **받은 뒤에도 기간 안에는 다시 받을 수 있습니다**: 다시 받을 때도 다운로드 이력을 남깁니다.

##### DRM

- **DRM은 화면에 표시하지 않습니다**: 저장할 때 문서보안 솔루션이 파일을 자동으로 암호화하고, 사용자가 할 일은 없습니다.
- **DRM 해제(반출)는 예외로 다룹니다**: 승인이 필요하면 요청형으로 받습니다.
- **DRM 해제를 어디에서 처리할지는 가안입니다**: BSS에서 요청하거나 문서보안 솔루션의 반출 화면으로 연결합니다. 외부 화면으로 연결할 때는 [외부 화면 연동 처리](integration-ux.html)를 따릅니다.

##### 화면마다 정하는 값

이 UX 패턴은 흐름과 규칙만 정하고, 아래 값은 화면을 설계할 때 채웁니다.

- 다운로드 권한
- 걸리는 관문과 사유코드 목록
- 요청형으로 바꾸는 기준 (예. 건수)
- 파일 형식
- 요청형 파일의 보관 기간

#### 실제 예시

탭마다 위 규정의 한 경우를 담았습니다.

유의사항목업의 알림 패널과 알림 항목은 가안입니다.
[요청형의 상태와 알림](#request)이 확정되면 함께 바꿉니다.

1. 바로 받기 탭에서 ‘엑셀 다운로드’를 누릅니다.
2. 관문 거쳐 받기 탭에서 ‘엑셀 다운로드’를 누르고, 사유와 비밀번호를 입력해 받습니다.
3. 같은 탭에서 다시 ‘엑셀 다운로드’를 누르고, 해제한 파일을 골라 ‘다운로드 요청’을 누릅니다.
4. 요청해서 받기 탭에서 ‘엑셀 다운로드’를 누릅니다.
5. 알림 배지가 바뀌면 사이드 내비게이션 바의 ‘알림’을 열어 ‘다운로드’를 누릅니다.
6. 첨부 파일 · 권한 탭에서 행마다 다운로드 아이콘을 누르고, 잠긴 ‘전체 다운로드’도 누릅니다.

파일 다운로드하기 · 네 가지 경우새 탭에서 크게 보기※ 예시 이미지 — 레이아웃/디자인은 확정 아님. 패턴 구조만 참고.
#### Do / Don't

###### Do · 이렇게 합니다

- 권한이 없는 다운로드 버튼은 잠금 아이콘으로 누르기 전에 구분되게 합니다.
- 걸리는 관문을 다운로드 설정 팝업 하나에 모아 묻습니다.
- 개인정보가 담긴 파일은 마스킹한 파일을 기본으로 받게 합니다.
- 요청형으로 바뀌면 그 이유를 팝업에 적습니다.
- 요청한 파일은 알림에서 바로 받게 합니다.

###### Don't · 이건 피합니다

- 누른 뒤에야 권한이 없다고 알리지 않습니다.
- 관문마다 팝업을 따로 띄우지 않습니다.
- 관문이 없는데 확인만 받으려고 팝업을 띄우지 않습니다.
- 요청한 파일이 준비될 때까지 사용자를 기다리게 하지 않습니다.
- 비밀번호를 파일 이름이나 알림에 적지 않습니다.
