통합 레벨이 정해진 뒤 화면에서 실제로 무엇을 하는지를 규정합니다.
내장형은 구분 없이 하나의 화면으로 보이게 하고, 이탈형은 컨텍스트가 끊긴다는 것을 분명히 알립니다.

#### 개요 · 언제 쓰나요?

[통합 레벨 프레임워크](integration-levels.html)에서 레벨을 정하면, 화면에서 할 조치는 두 갈래로 갈립니다.
Lv1부터 Lv3의 내장형은 경계를 지우고, Lv4와 Lv5의 이탈형은 경계를 드러냅니다.
다섯 레벨을 두 갈래로 묶는 이유는, 조치의 목적이 레벨보다 실행 위치에서 갈리기 때문입니다.

###### ✓ 이럴 때 사용합니다

- 통합 레벨을 확정한 뒤 화면 설계를 시작할 때
- 외부 화면의 진입점을 메뉴에 배치할 때
- 외부 화면이 BSS 화면 안에 들어올 때의 접합부를 정리할 때

###### ✕ 다른 패턴을 사용합니다

- 아직 통합 레벨이 정해지지 않았을 때 → 통합 레벨 프레임워크를 먼저 봅니다

핵심 원칙내장형은 사용자가 외부 기능임을 알 필요가 없게 만듭니다.
이탈형은 사용자가 외부로 나간다는 것을 반드시 알게 만듭니다.
같은 목표에서 갈라진 두 방향이며, 중간은 두지 않습니다.

#### 내장형 · Lv1 ~ Lv3

Lv1과 Lv2는 사용자가 구분할 수 없습니다.
Lv2도 프레임으로 탑재하지만 통신으로 경계를 메우므로 결과가 같습니다.
Lv3은 통신이 없어 완전히 같게 만들 수 없으므로, 남는 차이를 어디에 둘지를 아래에서 정합니다.
어느 레벨이든 외부이동 아이콘이나 '외부' 라벨은 붙이지 않습니다.

프레임 안은 이 가이드를 그대로 지키므로(디자인 토큰·Loading·Empty·Error·버튼 배치·상태 표기), 이 문서는 프레임 경계를 넘는 항목만 규정합니다.
프레임이 없는 Lv1은 해당하지 않습니다.

| 경계 항목 | Lv2 | Lv3 |
| --- | --- | --- |
| 스크롤 | 프레임 높이를 셸에 알리고 페이지가 스크롤합니다 | 프레임이 본문을 채우고 직접 스크롤합니다. 바깥에 다른 모듈을 두지 않습니다 |
| 화면 전체 오버레이 | 프레임 바깥에 요청해 띄웁니다 | 프레임 안에서 띄웁니다 |
| 화면 전환 | 셸에 알려 브레드크럼·화면 제목이 따라가게 합니다 | 페이지 전환을 만들지 않습니다 |
| 세션 만료 | 바깥에 알려 BSS 공통 처리로 넘깁니다 | 먼저 끊기지 않게 하고 프레임 안 조작도 활동으로 봅니다. 끊기면 다시 불러오기를 안내합니다 |
| 테마·언어 | 통신으로 즉시 반영합니다 | 진입 시점에 전달하고, 바꾸려면 다시 불러옵니다 |

지키지 않으면 스크롤이 이중으로 겹치고, 오버레이가 프레임 박스 안에 갇히고, 셸의 위치 표시가 첫 진입 상태에 머무릅니다.
Lv2는 저장처럼 결과를 확정하는 처리를 바깥으로 연동하지 않고 프레임 안에서 완결합니다.
Lv3의 구성은 프레임 안이 한 화면으로 완결되는 기능일 때 성립하므로, 여러 화면을 오가야 하거나 바깥에 BSS 모듈을 함께 두어야 하면 Lv2를 선택합니다.

#### 이탈형 · Lv4 ~ Lv5

컨텍스트의 단절을 분명히 알립니다.
창이 분리되며 생긴 단절을 미리 알려 통제감을 주고, 문제가 생겼을 때 조치 주체가 어디인지 인지하게 합니다.

Lv4는 레이어 팝업으로 열려 SSO로 로그인이 이어지고, Lv5는 새 창으로 나가 별도 로그인이 필요합니다.
로그인이 이어지는지 여부가 갈리므로 알려야 할 것도 갈립니다.

1
##### 메뉴 진입점 표기

사이드 내비게이션 바·사이트맵의 메뉴 항목 우측에 외부이동 아이콘을 노출합니다. 팝업 전용 메뉴는 별도 아이콘으로 구분합니다.

Lv4 · Lv52
##### 로그인 세션 연계 표기

현재 사용자를 기준으로 SSO를 전달합니다. 어느 사용자로 열렸는지 창 타이틀에 표시하며, 창 타이틀은 BSS가 관리합니다.

Lv43
##### 창열림 토스트 표기

창이 열릴 때 화면 하단에 솔루션 제공 주체를 표기하는 토스트를 띄우고, 3~4초 후 사라집니다.

Lv44
##### 별도 로그인 안내

창을 만들기 전에 확인 팝업을 띄워 별도 로그인이 필요함을 알립니다. 레이어가 아니라 새 창으로 실행합니다.

Lv5유의사항사용자의 인지 없이 팝업이나 새 창을 띄우지 않는 것이 핵심입니다.
사용 문의나 오류 문의를 위해서라도 서비스 제공 주체를 확실히 인지시키는 편이 사용자에게 유리합니다.
Lv4는 컨텍스트가 끊겨 로그인 세션의 유지 여부를 사용자가 확인할 수 없으므로, 이를 알리는 보조 UI 요소가 필요합니다.

#### 실제 예시

이탈형 조치 네 가지를 한 가지 케이스로 보여 주는 예시입니다.
Lv4의 조치가 셋(진입점 표기·세션 연계 표기·창열림 토스트), Lv5의 조치가 둘(진입점 표기·별도 로그인 안내)입니다.
규정은 위 **이탈형 · Lv4 ~ Lv5**가 소유합니다.

##### 메뉴 진입점 표기 · Lv4 · Lv5

아이콘 두 가지를 견주는 국면입니다.
아이콘이 없는 위쪽 두 항목과의 차이도 함께 봅니다.

##### 로그인 세션 연계 표기 · Lv4

팝업이 열린 상태입니다.
타이틀 왼쪽 칩에 어느 사용자로 열렸는지 표기된 것을 확인합니다.

##### 창열림 토스트 표기 · Lv4

창이 열린 직후의 상태입니다.
화면 하단 토스트에 솔루션 제공 주체가 적힌 것을 확인합니다.

##### 별도 로그인 안내 · Lv5

창을 만들기 전 확인 팝업이 뜬 상태입니다.
별도 로그인이 필요하다는 안내와 취소·이동 버튼을 확인합니다.

#### Do / Don't

###### Do · 이렇게 합니다

- 내장형은 프레임 안 화면이 이 가이드의 UX 패턴을 모두 만족시키게 합니다.
- 내장형에서 프레임 경계를 넘는 항목만 별도로 정의합니다.
- Lv3은 프레임이 본문을 단독으로 차지하게 합니다.
- 이탈형은 메뉴 진입점에서 외부로 나간다는 것을 미리 알립니다.
- 이탈형은 창이 열린 뒤에도 어느 서비스인지, 어느 사용자로 열렸는지 확인할 수 있게 합니다.

###### Don't · 이건 피합니다

- 내장형에 외부이동 아이콘이나 '외부' 라벨을 붙이지 않습니다.
- Lv3의 프레임 안에서 페이지를 전환하지 않습니다.
- iframe이 자체 스크롤을 갖게 두지 않습니다. (Lv3은 예외)
- 프레임 안의 저장을 프레임 바깥으로 연동하지 않습니다.
- 사용자에게 알리지 않고 팝업이나 새 창을 띄우지 않습니다.
