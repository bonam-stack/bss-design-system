표준 화면 틀을 벗어나 독립 애플리케이션처럼 구성하는 특수형 화면의 적용 기준입니다.
무엇을 반드시 지키고 무엇을 자유롭게 두는지를 가릅니다.

#### 개요 · 언제 쓰나요?

특수형은 독자적인 로직을 갖춘 툴 성격의 기능을 하나의 독립된 애플리케이션으로 만드는 화면입니다.
반복해서 쓰는 업무 화면이 아니라 과업의 진행 방식이 그 안에서 격리되는 화면이므로, 표준 화면 틀과 공통 UX 패턴을 그대로 적용하면 오히려 작업 효율이 떨어집니다.
격리되는 것은 진행 방식이며, 값을 주고받는 연결은 별개입니다.
이 문서는 특수형으로 판정한 화면에서 지켜야 하는 것과 자유롭게 두는 것의 경계를 규정합니다.

###### ✓ 이럴 때 사용합니다

- 독자적인 계산·시뮬레이션·편집 로직을 갖춘 툴을 화면으로 만드는 경우
- 표준 화면 틀에 담으면 작업 동선이 길어져 효율이 떨어지는 경우

###### ✕ 다른 패턴을 사용합니다

- 조회·상세·수정·생성이 비선형으로 일어나는 일반 업무 → [컨텐트 모듈 개요](layout-content.html)
- 단계가 순서대로 이어지는 절차형 업무 → [노드형 화면](layout-node.html)

#### 특수형으로 판정한 뒤에

특수형인지 가르는 두 조건은 [업무 화면 편성](work-composition.html)이 규정합니다.
판정을 마친 화면에 무엇을 지키게 하고 무엇을 자유롭게 둘지를 아래에서 정합니다.

#### 반드시 지키는 것

브랜드 정체성과 최소한의 예측 가능성을 위해 아래 넷은 공통 가이드를 그대로 따릅니다.

1. 컬러 시스템Primary · Secondary · Neutral 팔레트를 그대로 씁니다. 상태 색도 규정대로 씁니다. (성공=초록 · 경고=주황 · 오류=빨강 · 정보=파랑)
2. 피드백 · 알림 패턴오류·성공·경고 메시지의 토스트와 다이얼로그 규격을 따릅니다. 폼 입력값 검증 오류의 위치와 스타일도 같게 씁니다.
3. 타이포그래피 · 아이콘지정된 폰트 패밀리와 헤딩·본문 스케일, 행간·자간을 따릅니다. 아이콘은 시스템 표준 세트만 씁니다.
4. 업무 연결다른 업무에서 값을 받고 결과를 넘기는 방식은 [업무 연결](work-connect.html)의 규격을 따릅니다. 안에서 어떻게 처리하든 밖과 주고받는 접점은 표준입니다.

#### 자유롭게 두는 것

작업 효율을 우선하도록 레이아웃과 과업 흐름에는 자율성을 둡니다.
자율은 화면 안에서 벌어지는 일에 한합니다.

- **레이아웃 구조**: 표준 화면 틀(GNB·사이드 내비게이션 바)을 벗어난 전체 화면 캔버스 · 분할 뷰 · 다중 패널 구조를 허용합니다. 영역을 나누고 접었다 펴는 구성도 자유롭게 짭니다.
- **과업 흐름 · 상호작용**: 단계를 밟는 위저드 대신 한 화면에서 바로 실행하는 구조를 권장합니다. 인라인 편집 · 드래그 앤 드롭 · 다중 선택 일괄 처리 같은 툴 특화 조작을 자유롭게 씁니다.
- **컴포넌트 조합**: 데이터 밀도가 높은 전용 테이블 · 커스텀 툴바 · 단축키 배치를 허용합니다.

#### Do / Don't

###### Do · 이렇게 합니다

- [업무 화면 편성](work-composition.html)의 두 판정 조건에 모두 해당할 때만 특수형으로 편성합니다.
- 컬러 · 상태 색 · 피드백 규격 · 타이포그래피 · 아이콘은 공통 가이드를 그대로 씁니다.
- 레이아웃과 과업 흐름은 작업 효율을 기준으로 자유롭게 짭니다.
- 한 화면에서 바로 실행하는 구조를 먼저 검토합니다.
- 값을 받고 넘기는 접점은 업무 연결 규격을 따릅니다.

###### Don't · 이건 피합니다

- 조건에 못 미치는 화면을 특수형으로 빼지 않습니다.
- 자율 범위를 컬러 · 피드백 · 타이포그래피 · 업무 연결까지 넓히지 않습니다.
- 격리된다는 이유로 값을 주고받는 연결까지 끊지 않습니다.
- 임의의 아이콘 스타일을 섞어 쓰지 않습니다.
- 툴 성격의 화면을 표준 화면 틀에 억지로 맞춰 동선을 늘리지 않습니다.
