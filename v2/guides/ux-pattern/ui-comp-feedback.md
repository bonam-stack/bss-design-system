처리 상태와 메시지를 사용자에게 전달하는 컴포넌트를 규정합니다.
메시지를 어떤 방식으로 전달하는지와, 상태 · 보조 정보 · 작업 메뉴 · 로딩 상태를 무엇으로 표시하는지를 정의합니다.

#### 개요 · 언제 쓰나요?

Feedback & Notification 은 시스템의 상태와 처리 결과를 사용자에게 알리는 UI 단위입니다.
무엇을 알리는지와 사용자의 개입이 얼마나 필요한지에 따라 전달 방식이 구분됩니다.

이 문서는 메시지 전달의 공통 기준과 각 컴포넌트의 규격을 정의합니다.
별도 문서가 있는 컴포넌트는 그 문서를 따릅니다.

###### ✓ 이럴 때 사용합니다

- 상태나 처리 결과를 알리는 요소를 설계하는 경우
- 같은 상황에 어떤 전달 방식을 사용할지 결정하는 경우

###### ✕ 다른 패턴을 사용합니다

- 입력값 오류 표시 → [폼 유효성 체크](resp-form-validation.html)
- 화면 전체가 실패한 경우 → [전역 예외 화면](resp-error-page.html)

#### 공통 설계 기준

메시지를 전달하는 컴포넌트에 공통으로 적용합니다.

- **위치**: 사용자 행동과 가까운 위치에 배치합니다.
- **전역 노출**: 전역 안내는 화면 상단의 별도 영역에 표시합니다.
- **지속성**: 중요도가 높을수록 오래 유지합니다.
- **중복 노출**: 같은 메시지를 여러 위치에 함께 표시하지 않습니다.

#### 메시지 유형

무엇을 알리는지에 따라 여섯 가지로 구분하며, 유형마다 받는 문서가 다릅니다.

| 유형 | 기준 | 규격을 갖는 문서 |
| --- | --- | --- |
| 안내 (Informational) | 정보 전달 중심 | [토스트·스낵바](resp-toast.html) |
| 성공 (Success) | 작업 완료 안내 | [토스트·스낵바](resp-toast.html) |
| 검증 (Validation) | 입력 오류 안내 | [폼 유효성 체크](resp-form-validation.html) |
| 오류 (Error) | 처리 실패 안내 | [확인·경고 다이얼로그](resp-dialog.html) |
| 경고 (Warning) | 위험 사전 안내 | [확인·경고 다이얼로그](resp-dialog.html) |
| 확인 (Confirmation) | 사용자 의사 확인 | [확인·경고 다이얼로그](resp-dialog.html) |

#### 별도 문서가 있는 컴포넌트

무엇을 하는 컴포넌트인지와 어느 문서를 따르는지 정리합니다.

| 컴포넌트 | 무엇을 하나 | 규격을 갖는 문서 |
| --- | --- | --- |
| Toast / Snackbar | 화면을 막지 않고 처리 결과를 알립니다 | [토스트·스낵바](resp-toast.html) |
| Alert · Dialog Popup | 실행하기 전에 의사를 묻거나 배경 조작을 막고 확인을 받습니다 | [확인·경고 다이얼로그](resp-dialog.html) |
| Modal Popup | 화면을 덮고 별개의 내용을 표시합니다 | [상세 팝업](popup.html) · [전체 화면 팝업](view-full-popup.html) |
| Toolbar | 화면이나 영역의 조작 요소를 한 줄에 모아 둡니다 | [노드형 화면](layout-node.html)의 HUD |

#### 상태 · 정보 표시

항목에 붙어 상태나 속성을 짧게 표시합니다.

##### Badge

항목에 붙여 상태 · 수량 · 변경을 최소한의 요소로 표시합니다.

- **Text**: 텍스트 기반의 기본 형태입니다.
- **Dot**: 점과 텍스트로 상태를 간결하게 표시합니다. 배경을 두지 않습니다.
- **Count**: 알림 수 또는 항목 개수처럼 수량을 전달합니다.
- **Indicator**: 신규 컨텐트나 변경 상태를 표시합니다. 공간 제약이 있으면 점만 남깁니다.
- **Status**: 강한 대비의 배경색으로 중요하게 인지해야 할 요소에 사용합니다.
- **사용하지 않는 경우**: 분류나 속성을 표시하는 경우에는 Tag 를 사용합니다.

##### Tag

항목의 분류 · 속성 · 상태를 짧은 라벨로 표시합니다.

- **Category**: 컨텐트를 유형별로 구분합니다.
- **Status**: 진행 상태나 현재 상태를 표시합니다.
- **Label**: 항목의 속성이나 특징을 표시합니다.
- **Negative**: 실패 · 오류처럼 부정적인 정보를 강조합니다.
- **Caution**: 사용자의 확인이 필요하거나 주의가 요구되는 정보를 표시합니다.
- **Highlight**: 보조 안내 및 참고 정보를 강조합니다.
- **Neutral**: 중립적인 상태와 정보를 표현합니다.
- **사용하지 않는 경우**: 상태 · 수량 · 알림을 표시하는 경우에는 Badge 를 사용합니다.

##### Chip

값을 담아 조건이나 대상을 표시하며, 누르거나 지울 수 있습니다.

- **Basic Chip**: 텍스트로 정보를 전달하며 삭제 같은 상호작용을 제공하지 않습니다.
- **Count Chip**: 아이콘과 텍스트에 수치를 함께 표시해 현황을 전달합니다. 테두리를 두지 않아 조건을 담는 칩과 구분됩니다.
- **Filter Chip**: 텍스트와 수치로 필터링 상태를 표시하며 삭제 버튼 없이 단독으로 제공합니다. 수치는 세 자리까지 표시하고 넘으면 `+` 로 생략합니다.
- **Remove Chip**: 삭제 아이콘을 제공하여 담긴 조건을 하나씩 해제합니다. 수치는 필요한 경우에만 함께 표시합니다.

화면별 용례는 별도 문서가 갖고 있습니다. 조회 조건 칩은 컨텐트 상세검색, 필터 적용 상태 칩과 퀵 액션의 칩은 테이블 모듈 공통 정의, 업무 탭은 GNB를 따릅니다.
#### 보조 정보 표시

##### Tooltip / Popover

요소에 딸린 보조 설명이나 내용을 띄워 표시합니다.
무엇으로 여는지가 둘을 가르는 기준입니다.

- **Tooltip**: 대상에 마우스를 올리면 표시하고, 벗어나면 사라집니다.
- **Popover**: 대상을 클릭하면 표시하고, 다시 누르거나 바깥을 누르면 닫힙니다.
- **담는 내용**: Tooltip 은 문구만 둡니다. 링크나 닫기가 필요하면 Popover 를 사용합니다.
- **레이어 순위**: 전역 순위를 갖지 않고, 자기를 띄운 부모 안에서만 위로 옵니다.

레이어가 겹칠 때의 규정은 레이어 구조를 따릅니다.
#### 작업 메뉴 표시

##### Context Menu

항목에 대해 바로 실행할 수 있는 작업을 모아 보여 주는 메뉴입니다.
행 · 카드처럼 개별 항목에 딸린 작업을 담습니다.
화면이나 영역 단위의 작업은 [버튼 구조 및 동작](layout-action.html)의 버튼 그룹을 사용합니다.

- **여는 방법**: 항목의 케밥(⋮) 버튼을 눌러 엽니다.
- **구성**: 케밥 버튼과 작업 목록(메뉴) 둘로 이루어집니다.
- **상태**: Default · Selected(메뉴가 열리고 고른 항목을 강조) · Hovered 로 나뉩니다.
- **위치**: 케밥 버튼 아래에 엽니다. 화면 끝에 닿으면 반대쪽으로 엽니다.
- **닫기**: 바깥을 누르거나, `Esc` 를 누르거나, 항목을 고르면 닫힙니다.
- **레이어 순위**: 전역 순위를 갖지 않고, 자기를 띄운 부모 안에서만 위로 옵니다. ([레이어 구조](layout-layer.html))

메뉴에 담는 작업은 다음 규칙을 따릅니다.

- **되돌리기 어려운 작업**: 삭제처럼 되돌리기 어려운 작업은 빨간 글자로 구분하고, 목록 맨 아래에 구분선으로 떼어 둡니다. 누르면 바로 실행하지 않고 [확인·경고 다이얼로그](resp-dialog.html)로 확인을 받습니다.
- **쓸 수 없는 작업**: 권한이 없어 쓸 수 없는 작업은 메뉴에 두지 않습니다. 조건이 맞지 않아 지금만 쓸 수 없는 작업은 흐리게 두어, 있다는 것은 알 수 있게 합니다.

#### 로딩 상태 표시

처리가 진행되는 동안 무엇을 보여 줄 것인지에 따라 세 가지로 구분합니다.
처리 중임만 알리려면 Spinner, 불러올 컨텐트의 자리를 채우려면 Skeleton, 진행되는 정도를 보이려면 Progress Bar 를 사용합니다.

##### Spinner

처리가 진행 중이라는 사실을 표시합니다.

- **사용하지 않는 경우**: 진행되는 정도를 보여야 하는 경우에는 Progress Bar 를 사용합니다. 진행 상태를 단계로 표현해야 하는 경우에도 사용하지 않습니다.
- **즉시 반응**: 사용자 조작 직후 바로 표시합니다.
- **종료 처리**: 완료 시 즉시 제거합니다.
- **크기 선택**: 화면 전체를 기다리게 하면 크게, 리프레시처럼 짧은 대기에는 작게 사용합니다.
- **의미 보강**: 무엇을 처리하는지 텍스트로 함께 알립니다. (권장) 필요하면 처리한 수치를 문구에 함께 적습니다.

##### Skeleton

불러올 컨텐트의 자리를 미리 블록 형태로 표시합니다.

- **사용하지 않는 경우**: 컨텐트 형태를 예측할 수 없으면 Spinner 를 사용합니다.
- **구조 일치**: 실제 컨텐트와 같은 레이아웃 구조로 표시하여 로딩 전과 후에 레이아웃이 바뀌지 않게 합니다.
- **형태 선택**: 실제 요소의 모양을 따릅니다. 원형 요소는 Circle, 이미지는 Rectangle, 텍스트는 Text, 라벨과 태그는 Capsule, 그래프는 Graph 를 사용합니다.
- **즉시 노출**: 화면에 진입하는 즉시 표시합니다.
- **모션**: 하이라이트가 한 방향으로 일정한 속도로 지나가게 하여 로딩 중임을 알립니다. 스켈레톤 안에만 적용하고 화면 전체로 넓히지 않으며, 짧은 로딩 구간에서는 생략합니다.

목록의 조회 상태별 스켈레톤 처리는 테이블 모듈 공통 정의를 따릅니다.
##### Progress Bar

작업이 어디까지 진행되었는지 막대의 길이로 표시합니다.

- **사용하지 않는 경우**: 처리 중이라는 사실만 알리면 되는 경우에는 Spinner 를 사용합니다.
- **표현 방식**: 진행 정도는 막대의 길이로 표현하고, 진행률 수치는 함께 표시할 수 있습니다.
- **상태 문구**: 수치를 표시하지 않는 경우 무엇을 처리하는 중인지 문구로 알립니다.
- **진행 흐름**: 진행 상태는 실제 상태에 맞게 갱신하며, 뒤로 되돌아가지 않게 합니다.
- **완료 표현**: 완료 상태는 진행 중과 명확히 구분하여 표시합니다.
- **상태**: 진행 중 · 완료 · 오류 · 비활성 네 가지를 구분합니다.

#### Do / Don't

###### Do · 이렇게 합니다

- 메시지는 사용자가 조작한 자리와 가까운 곳에 표시합니다.
- 상태 · 수량은 Badge, 분류 · 속성은 Tag 로 구분하여 사용합니다.
- 조건을 해제할 수 있어야 하면 삭제 아이콘이 있는 칩을 사용합니다.
- 보조 설명은 Tooltip, 눌러서 여는 내용은 Popover 로 구분합니다.
- 무엇을 보여 줄 것인지 먼저 정하고 로딩 표시를 결정합니다.
- 로딩이 끝나면 표시를 즉시 제거하고 실제 컨텐트로 바꿉니다.

###### Don't · 이건 피합니다

- 같은 메시지를 여러 위치에 함께 표시하지 않습니다.
- 세 자리를 넘는 수치를 칩에 그대로 표시하지 않습니다.
- 처리 중임만 알리면 되는 자리에 Progress Bar 를 사용하지 않습니다.
- 실제 컨텐트와 다른 구조로 Skeleton 을 표시하지 않습니다.
- Tooltip 과 Popover 에 전역 레이어 순위를 주지 않습니다.
