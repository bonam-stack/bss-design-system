### 엑셀 대량 등록

다량의 데이터를 엑셀 파일로 등록·수정하는 기능이며, 이 패턴의 핵심은 유효성 검증입니다.
파일을 올리는 것보다, 시스템에 반영하기 전에 오류를 검증하고 그 결과에 따라 후속 처리 흐름을 결정하도록 설계합니다.

#### 개요 · 언제 쓰나요?

엑셀 대량 등록은 여러 건의 데이터를 파일 하나로 한 번에 등록하거나 수정하는 방법입니다.
파일을 올리는 방법보다 데이터를 어떻게 검증하고, 검증 결과에 따라 무엇을 하게 할지를 먼저 설계합니다.
업무 성격에 맞는 검증 방식을 고르고, 그 방식에 맞는 결과 화면과 후속 흐름을 함께 정하는 것이 이 패턴의 목적입니다.

###### ✓ 이럴 때 사용합니다

- 여러 건의 데이터를 한 번에 등록·수정하는 테이블 화면
- 정해진 템플릿(양식)으로 반복 업로드하는 업무

###### ✕ 다른 패턴을 사용합니다

- 소량을 화면에서 직접 입력·저장 → Form Based Patterns
- 단계·흐름을 따라 진행 → Node Patterns

#### 유효성 검증 방식

유효성 검증 방식은 업무 목적에 따라 두 가지 중 하나를 골라 설계합니다.
두 방식은 검증 로직만 다른 것이 아니라, 검증 이후의 결과 화면과 후속 처리 흐름까지 함께 달라집니다.

1. 예외 처리 방식**전체를 끝까지 검증 → 결과 일괄 제공 · 정상만 반영**: 전체 데이터를 모두 검증한 뒤 결과를 한 번에 제공합니다. 오류는 예외로 두고 정상 데이터만 반영하며, 전체 오류를 한 번에 확인해야 하는 업무에 적합합니다. 검증 후 정상 데이터 업로드·오류 확인·오류 행 다운로드 같은 후속 작업으로 이어집니다.
2. 무결성 검증 방식**첫 오류에서 즉시 중단 → 수정 후 처음부터 재검증**: 순차적으로 검증하다가 첫 번째 오류가 발생하면 즉시 검증을 중단합니다. 하나라도 오류가 있으면 진행하지 않으므로, 데이터 전체가 온전해야(무결) 다음 업무를 진행할 수 있는 업무에 적합합니다. 오류 수정 후 처음부터 다시 검증하는 흐름을 기본으로 합니다.

기억할 점검증 방식은 검증 로직이 아니라 결과 화면·후속 흐름까지 함께 정하는 선택입니다.
업무 특성(전체 오류를 한 번에 볼 것인가 / 오류를 먼저 바로잡아야 하는가)에 따라 방식을 먼저 정하고, 그에 맞는 흐름을 설계합니다.

#### 백그라운드 검증 프로세스

대량 데이터 검증은 시간이 오래 걸릴 수 있습니다.
사용자가 검증이 끝날 때까지 대기하지 않도록, 검증은 백그라운드에서 계속 수행되고 완료 시점에는 사용자의 위치에 맞게 안내합니다.

검증이 진행되는 동안의 동작입니다.

##### 백그라운드 전환

팝업을 닫거나 "백그라운드에서 진행" 버튼을 누르면 백그라운드로 전환됩니다.
전환 후에도 검증은 중단되지 않고 계속되며, 사용자는 팝업을 떠나 다른 업무를 이어서 할 수 있습니다.

##### 진행 상태 확인

팝업을 닫아도 화면 우상단 액션 영역에서 현재 검증 진행 상태를 확인할 수 있습니다.
진행 표시를 다시 누르면 진행 중인 검증 팝업으로 돌아갑니다.

##### 업로드 조건 잠금

검증이 진행되는 동안에는 업로드 조건(파일 변경·검증 방식 변경 등)을 바꿀 수 없도록 합니다.
진행 중인 검증과 조건이 어긋나지 않게 합니다.

검증이 완료되면 사용자의 위치에 맞게 안내합니다.

##### 완료 · 팝업이 열려 있을 때

이미 팝업을 보고 있으므로 플로팅 알림을 띄우지 않고, 팝업 내부 상태만 완료로 바꿔 결과를 바로 보여 줍니다.

##### 완료 · 팝업이 닫혀 있을 때

다른 업무 중일 수 있으므로 놓치기 어려운 플로팅 알림으로 알리고, 눌러서 결과를 확인하도록 유도합니다.
예외 처리 방식이 오류로 중단된 경우에도 같은 방식으로 안내합니다.

기억할 점진행 상태를 항상 드러내고, 진행 중에는 조건 변경을 막습니다.
완료 안내는 사용자의 위치(팝업 열림 / 닫힘)에 맞춰, 중복 알림도 놓침도 없게 설계합니다.

#### 검증 결과

검증 결과는 전체 / 정상 / 오류 기준으로 구분해 제공합니다.
오류는 행 단위와 오류 사유를 함께 보여 주고, 결과 이후의 후속 처리는 선택한 검증 방식에 따라 달라집니다.

1. 전체 · 정상 · 오류 구분결과를 전체 / 정상 / 오류로 나눠 보여 주고, 각 건수는 탭(또는 칩) 한 곳에서 제공합니다. 같은 정보를 다른 위치에 중복해 표시하지 않습니다.
2. 오류 확인 · 다운로드오류 데이터는 어떤 값이 왜 잘못됐는지 사유와 함께 행 단위로 보여 줍니다. 오류 행만 따로 내려받아 수정할 수 있게 합니다.
3. 예외 처리 방식 · 정상 업로드예외 처리 방식은 정상 데이터만 업로드합니다. 정상 건수와 실행을 한 버튼에 묶어, 무엇이 몇 건 반영되는지 명확히 보여 줍니다.
4. 무결성 검증 방식 · 재검증무결성 검증 방식은 정상만 부분 업로드하지 않습니다. 오류를 바로잡은 뒤 처음부터 다시 검증하도록 유도하며, 오류가 남아 있는 동안에는 업로드로 넘어가지 않게 합니다.

기억할 점건수 등 같은 결과 정보는 한 곳에서만 제공하고, 여러 위치에 중복 표시하지 않습니다.
결과 데이터가 많으면 페이지네이션을 기본으로 사용합니다.

#### 실제 예시

회선수 제한 예외 처리 화면의 엑셀 대량 등록입니다.
업로드 버튼으로 팝업을 열어 유효성 검증 · 백그라운드 진행 · 완료 알림 · 결과 확인(전체 / 정상 / 오류)까지 동작을 직접 확인할 수 있습니다.

회선수 제한 예외 처리 · BSS 표준 화면새 탭에서 크게 보기※ 예시 이미지 — 레이아웃/디자인은 확정 아님. 패턴 구조만 참고.참고검증 방식(예외 처리 · 무결성)의 구분은 위 설명을 따르며, 아래 예시 화면은 전체 유효성 검증 흐름(유효성 검사 → 백그라운드 진행 → 결과 확인)을 담습니다.
전체 검증 동작 자체는 화면에서 "유효성 검사"로 표기합니다.

#### Do / Don't

###### Do · 이렇게 합니다

- 검증 방식은 업무 성격으로 정합니다.
- 전체 오류를 한 번에 보고 정상만 반영해도 되면 예외 처리 방식을 씁니다.
- 하나라도 오류가 있으면 진행을 멈춰야 할 때는 무결성 검증 방식을 씁니다.
- 선택한 검증 방식에 맞춰 결과 화면과 후속 처리(정상 업로드 / 재검증)를 함께 설계합니다.
- 대량·장시간 검증이 예상되면 백그라운드 검증을 전제로 설계합니다.
- 진행 상태와 완료 안내를 사용자의 위치(팝업 열림 / 닫힘)에 맞게 설계합니다.
- 오류는 행·사유까지 확인하고 곧바로 수정으로 이어지게 합니다.
- 같은 결과 정보(건수 등)는 한 곳에서만 제공합니다.

###### Don't · 이건 피합니다

- 업무 목적과 무관하게 검증 방식을 습관적으로 정하지 않습니다.
- 선택한 방식과 어긋나는 후속 흐름을 설계하지 않습니다. (예외 처리 방식인데 첫 오류에서 멈추거나, 무결성 검증 방식인데 정상만 부분 업로드하는 식)
- 장시간 검증 동안 사용자를 팝업 앞에 붙잡아 두지 않습니다.
- 진행 상태·완료 여부를 사용자가 알 수 없게 감추지 않습니다.
- 오류 원인 없이 결과만 제시하지 않습니다.
- 같은 결과 정보를 여러 위치에 중복 배치하지 않습니다.
