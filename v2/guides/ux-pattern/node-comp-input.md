사용자에게서 값을 받아 저장하는 노드 모듈입니다.
입력과 CTA를 중심으로, 특이사항·기본 정보·가이드 정보를 필요에 따라 더합니다.

#### 개요 · 언제 쓰나요?

입력형은 노드 모듈 유형의 하나입니다.
사용자에게서 값을 받아 저장하는 노드 모듈을 어떤 구조로 설계하는지 규정합니다.
무엇을 입력하는지 맥락을 먼저 보여 주고, 그 아래에서 값을 채우게 한 뒤, 마지막 동작을 저장으로 마무리합니다.

###### ✓ 이럴 때 사용합니다

- 새 값을 작성해 저장할 때
- 연락처·주소처럼 기존 값을 고쳐 저장할 때
- 여러 항목의 리스트를 만들어 갈 때

###### ✕ 다른 노드 모듈 유형을 사용합니다

- 값을 읽기만 하면 → 조회형
- 정해진 값을 고르기만 하면 → 선택형
- 고객·상담사가 주고받아야 진행되면 → 상호작용형

##### 기본 틀

입력형 노드 모듈은 위에서 아래로 특이사항(선택) · 기본 정보(선택) · 입력 · 가이드 정보(선택) · CTA를 쌓습니다.
각 자리는 담는 데이터의 성격으로 정합니다.
입력 자리의 표현은 넣을 값의 성격에 따라 설계합니다.
공통 자리(특이사항·기본 정보·가이드 정보)는 조회형과 같은 역할·이름으로 두고, 입력이 이 패턴의 고유 표현입니다.

1. 특이사항 (선택 · 최상단)업무 대상의 특이사항이나 입력 전에 먼저 봐야 할 유의점을 콜아웃으로 알립니다. 기본은 두지 않고, 꼭 필요할 때만 표시하는 옵션 요소입니다. 입력에 집중하는 시야를 해치지 않도록 간결하게 씁니다.
2. 기본 정보 (선택)무엇을 입력하는지 맥락을 잡는 대상 정보를 담습니다. 필수가 아닌 옵션 요소입니다. 정보 요약을 기본으로 쓰되 미디어 카드 등 다른 표현으로도 둘 수 있습니다.
3. 입력이 모듈에서 값을 넣거나 고치는 핵심 자리입니다. 넣을 값의 성격에 따라 인라인 텍스트·텍스트영역·필드 옆 버튼·자동채움 등으로 달라집니다. 필요하면 여러 구성요소를 함께 편성할 수도 있습니다.
4. 가이드 정보 (선택)저장 후 영향이나 자동채움 근거처럼 판단을 돕는 안내를 짚어 줍니다. 필수가 아닌 옵션 요소입니다. AI 안내로 채울 수도 있고, 정해진 안내를 그대로 둘 수도 있습니다.
5. CTA‘저장’·‘다음’처럼 다음 동작을 실행하는 버튼입니다. 모든 노드 모듈에 공통이며 맨 아래로 분리하고, 입력형은 저장으로 마무리합니다.

특이사항 → 기본 정보 → 입력 → 가이드 정보 → CTA 순으로 쌓은 골격입니다.

#### 구성요소

입력 자리에 넣는 표현입니다.
인라인 텍스트가 기본이고, 나머지는 넣을 값의 성격에 따라 골라 씁니다.
일부는 다른 화면 유형에서 그대로 가져와 씁니다.

##### 인라인 텍스트

노드 모듈 안에서 값을 직접 타이핑해 넣는 기본 표현입니다.
라벨을 위에 두고 그 아래 풀폭 입력칸을 둡니다.

**규칙** 필드가 5~6개 이하인 가벼운 값에 사용합니다.
필수 항목은 컨트롤 배경으로 표시합니다.

##### 필드 옆 버튼

인라인으로 넣기 어려운 값은 검색으로 채우고, 검증이 필요한 값은 중복확인·인증 버튼을 필드 옆에 둡니다.

**규칙** 직접 타이핑이 어렵거나 검증이 필요한 값에만 씁니다.
검색으로 채우는 값은 읽기 전용으로 두어 직접 수정하지 못하게 합니다.

##### 텍스트영역

사유·메모처럼 긴 텍스트를 여러 줄로 입력하게 합니다. 한 줄 입력칸으로 부족할 때 사용합니다.
**규칙** 긴 서술이 필요한 값에만 사용합니다. 줄 수는 예상 분량에 맞춰 정합니다.

##### 자동채움

본인인증·기존 정보로 이미 채워진 필드입니다. 옅은 회색 읽기 전용으로 두어 직접 수정하지 못하게 하고, 작업자는 빈 칸만 채웁니다.
**규칙** 인증·기존값으로 채워진 필드는 읽기 전용 회색으로 표시합니다. 자동으로 채워지지 않으면 일반 활성 입력칸으로 둡니다.

##### 대기 · 현장 안내

노드 안에서 인라인으로 편집할 수 없는 값은, 무엇을 편집하는지 크게 안내하고 거대 팝업으로 편집하게 합니다.
상호작용형의 대기·현장 안내(Hero)를 그대로 가져와 씁니다.

**규칙** 노드에서 편집이 불가한 값(전체화면·거대 팝업 편집)에만 씁니다.

##### 진행률 바

대량·장시간 일괄 입력의 진행 정도를 막대와 퍼센트로 보여 줍니다.
엑셀 양식을 내려받아 작성한 뒤 파일로 올려 한꺼번에 값을 채워 넣는 형태이며, 업로드가 시작되면 0%에서 100%까지 막대가 채워집니다.

**규칙** 대량·장시간 입력에 사용합니다.
업로드로 시작하면 진행률 위에 업로드 버튼을 두고, 처리 중에는 실행 버튼을 눌림 방지 상태로 둡니다.
엑셀 양식 다운로드·작성은 [인라인 편집 테이블](grid-inline.html)의 엑셀 다운로드 규칙을 따르고, 엑셀 파일 업로드는 [엑셀 대량 등록](grid-excel-upload.html)의 엑셀 파일 업로드 규칙을 따릅니다.

#### 핵심 동작 · 상태

##### 자리와 표현

- 자리(영역)는 담는 데이터의 성격으로 정합니다. 위쪽에는 무엇을 입력하는지 맥락을, 가운데에는 값을 넣거나 고치는 입력 필드를 둡니다.
- 표현은 인라인 텍스트를 기본으로 권장하되, 넣을 값의 성격에 따라 다른 표현을 씁니다. (예. 값 후보가 정해져 있으면 드롭다운, 인라인으로 넣기 어렵거나 검증이 필요하면 필드 옆 버튼)
- 가장 단순한 형태(입력 + CTA)에서 출발해 필요한 표현만 더합니다.
- 구분선은 기본 정보와 필수 정보 사이에만 넣습니다. 필수 정보끼리는 제목으로 나뉘어도 넣지 않고, 가이드 정보 앞뒤에도 넣지 않습니다. CTA만 맨 아래로 분리합니다.
- 기본 정보의 영역 제목은 선택입니다. 제목 없이 내용만 두어도 되고, 내용만으로 무엇인지 읽히면 제목을 넣지 않습니다.

표현별 규칙은 위 구성요소의 각 표현 설명에 함께 적었습니다.
##### 입력형 고유 동작

- **가능하면 자동채움(auto fill-in)을 기본으로 적용합니다.** 본인인증·기존 정보로 채울 수 있는 값은 미리 채워 두고(읽기 전용 회색), 작업자는 빈 칸만 채우게 합니다. 자동으로 채울 수 없을 때만 직접 입력으로 둡니다.
- 휴대폰 번호·생년월일 같은 값은 숫자만 입력하면 하이픈·점이 자동으로 완성되게 합니다.
- 필수 항목은 컨트롤 배경으로 표시합니다.

##### CTA 활성 · 비활성 (진행 조건)

- 진행 조건이 있는 노드 모듈은 조건을 채우기 전까지 CTA를 **비활성**으로 둡니다. **비활성** = 아직 진행할 수 없는 상태(버튼이 눌리지 않음), **활성** = 조건을 모두 채워 다음으로 넘어갈 수 있는 상태입니다.
- 조건을 충족하는 순간 자동으로 활성으로 바뀝니다. (예. 필수 입력이 하나라도 비어 있으면 ‘저장’ 비활성 → 전부 채우면 활성)
- 입력값 검증·에러 표시는 [폼 유효성 체크](resp-form-validation.html)를 따릅니다.

##### 규모에 따른 배치

- 필드가 5~6개 이하이고 단일 분야면 노드 모듈 안에서 바로 인라인으로 입력합니다.
- 필드가 늘거나 여러 분야로 나뉘면 사이드 패널로 뺍니다. 리스트를 만들어 가는 입력은 추가 버튼으로 사이드 패널 폼을 엽니다.
- 입력할 행이 많은 일괄 입력은 전체화면 테이블 팝업으로 뺍니다.
- 대량·장시간 일괄 입력은 엑셀 양식으로 작성해 파일로 올리고, 진행률 바로 채워지는 정도를 보여 줍니다.
- 계산이 필요한 값은 뒤 화면을 가리지 않는 계산기 팝업으로 계산해 결과만 필드에 넣습니다.

##### 진행 표시

- 노드 모듈이 여러 단계(페이지)로 진행되면, 단계 표시는 모듈 안이 아니라 액션바에 둡니다. (예. 액션바 타이틀 ‘청약 정보 입력 (1/2)’)

#### Do / Don't

###### Do · 이렇게 합니다

- 노드 안에서의 클릭은 1~2회로 권장합니다. 한 노드에 과도한 단계·클릭을 만들지 않습니다.
- 가장 단순한 형태(입력 + CTA)에서 출발해 필요한 표현만 더합니다.
- 무엇을 입력하는지 맥락을 먼저 보여 주고, 그 아래에서 값을 채우게 합니다.
- 인증·기존값으로 채워진 필드는 자동채움으로 두어 빈 칸만 채우게 합니다.
- 필드가 많거나 여러 분야로 나뉘면 사이드 패널로, 행이 많은 일괄 입력은 전체화면 테이블로 뺍니다.
- 마무리는 저장 하나로 하고, 필수 값을 다 채워야 저장이 눌리게 합니다.

###### Don't · 이건 피합니다

- 맥락 없이 빈 입력 필드만 나열하지 않습니다.
- 인라인으로 넣기 어려운 값을 직접 타이핑하게 하지 않습니다. (→ 검색·필드 옆 버튼)
- 검증이 필요한 값을 그대로 저장하지 않습니다. (→ 중복확인·인증)
- 필드가 많은 입력을 노드 모듈 안에 다 펼치지 않습니다. (→ 사이드 패널·전체화면 테이블)
