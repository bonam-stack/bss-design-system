# DS 디자인 토큰 개발 가이드

> 토큰 v2.0.4 (피그마 BSS_DS_library_Component_v2.0 기준). DS가 관리하는 토큰 원본에서 생성한 파일이다. 받은 파일은 직접 고치지 않고, 변경이 필요하면 DS에 요청한다.
> 토큰 버전 1.0.0부터 토큰 이름을 바꾸거나 지우는 변경은 메이저 버전(2.0.0 등)에서만 한다. 바뀐 내용은 변경 이력(`02_CHANGELOG.md`)으로 함께 전달한다.

## 1. 받는 파일

| 파일 | 용도 |
| --- | --- |
| `tokens.css` | 토큰 전체를 CSS 변수로 정의한 파일. `:root`에 CSS 변수만 있다 |
| `tokens.d.ts` | CSS 변수 이름 타입. 자동완성과 오타 검사 |
| `component-specs.json` | 컴포넌트별 변형·사이즈·상태 → 변수 대응표 |
| `design-tokens.tokens.json` | 토큰 원본(DTCG 형식). 이름·값 조회와 변환용 |
| `00_개발-가이드.md` | 이 문서 |
| `01_컴포넌트명세/토큰/` | 컴포넌트별 토큰 목록, 사이즈별 값, 글자 스타일 |
| `01_컴포넌트명세/컴포넌트-구조명세.md` | 컴포넌트별 변형·속성·레이어 구조 |
| `02_CHANGELOG.md` | 버전별 변경 내역. 「삭제」「운영 출력 변경」은 코드 수정이 필요한 항목 |

- 적용 방식은 개발 환경에 맞게 정한다. 어떤 방식이든 CSS 변수 이름과 값은 `tokens.css`와 같아야 한다.
- 운영 변수: Semantic 368개(글자 스타일 단축 변수 포함), 컴포넌트 60종.

## 2. 이름 규칙

- **기준은 토큰 이름이다.** 원본의 경로 구간을 `-`로 이은 것이 토큰 이름이고, CSS 변수 이름은 토큰 이름에서 규칙 하나로 만든다.
- **규칙:** 앞에 `--`를 붙이고, 각 구간 안의 대문자 앞에 `-`를 넣은 뒤 전부 소문자로 바꾼다. 예외는 없다.
- 원본의 `$extensions["com.bss"].css`에 이 규칙의 결과가 적혀 있다.
- 원본을 다른 도구(Style Dictionary 등)로 변환해도 되며, 결과 이름은 이 규칙과 같아야 한다. 도구의 기본 변환은 그룹 경로를 이름에 붙여 결과가 달라질 수 있으니, 아래 표와 `tokens.css`로 결과를 비교한다.
- 숫자 구간: `p`는 소수점(`1p5` = 1.5), `minus`는 음수(`minus0p2` = -0.2).
- 상태 토큰이 딸린 기본값 토큰은 끝에 `-default`가 붙는다(예: `-hover`가 있는 Semantic).
- 컴포넌트 사이즈 단어(`button-action-small`의 `small`)와 Semantic 단계 단어(`size-icon-small`, `radius-small`)는 다른 척도다. 이름에는 값을 넣지 않으므로, 사이즈별 실제 값은 `01_컴포넌트명세/토큰/컴포넌트-토큰-[묶음].md`의 **사이즈별 값** 표에서 확인한다.

| 토큰 이름 | 원본 경로 | 피그마 변수 | CSS 변수 |
| --- | --- | --- | --- |
| `color-tBlue-50` | `primitive.color.tBlue.50` | `color/tBlue/50` | `--color-t-blue-50` |
| `font-lineHeight-16` | `primitive.font.lineHeight.16` | `font/lineHeight/16` | `--font-line-height-16` |
| `font-letterSpacing-minus0p2` | `primitive.font.letterSpacing.minus0p2` | `font/letterSpacing/minus0p2` | `--font-letter-spacing-minus0p2` |
| `borderWidth-1p5` | `primitive.borderWidth.1p5` | `borderWidth/1p5` | `--border-width-1p5` |
| `button-action-small-focusRing-radius` | `component.button.action.small.focusRing.radius` | `button/action/small/focusRing/radius` | `--button-action-small-focus-ring-radius` |
| `color-bg-neutral-stronger-default` | `semantic.color.bg.neutral.stronger.default` | `color/bg/neutral/stronger/default` | `--color-bg-neutral-stronger-default` |
| `button-primary-color-bg-default` | `component.button.primary.color.bg.default` | `button/primary/color/bg/default` | `--button-primary-color-bg-default` |

### 이름 구조

| 계층 | 이름 구조 | 예 |
| --- | --- | --- |
| Primitive | [분류]-[계열]-[단계]. 원시값이라 이름 끝이 값이다 | `color-gray-600`, `space-12`, `radius-6` |
| Semantic | [분류]-[속성]-[역할]-[강도]-[상태]. 컴포넌트를 모르는 역할 이름이다 | `color-bg-brand-strongest-hover`, `radius-small` |
| Component | [컴포넌트]-[유형·변형]-[사이즈]-[부품]-[분류]-[속성]-[상태] | `button-action-large-space-paddingX` |
| Semantic 화면 레이아웃 | space-[영역]-[섹션 변형]-[속성]. 컴포넌트가 아닌 화면 본문의 여백·간격이다. 섹션 변형은 `section`에만 붙는다 | `space-body-paddingX`, `space-section-spaced-gap` |

## 3. 값 변환 (원본 → CSS)

| 원본 | CSS | 예 |
| --- | --- | --- |
| 치수 `{"value": n, "unit": "px"}`, 분류가 `font-size`, `font-lineHeight`, `space`, `size` | rem (n ÷ 16) | `{"value": 12, "unit": "px"}` → `0.75rem` |
| 치수, 분류가 `radius`, `borderWidth`, `font-letterSpacing`, `effect` | px | `{"value": 6, "unit": "px"}` → `6px` |
| 치수 0 | `0` | |
| 색 | hex 그대로 | `#3617CE` |
| 글꼴 | 글꼴 이름 + 대체 글꼴 | `"Pretendard", -apple-system, …` |
| 굵기 | 숫자 | `500` |
| 참조 `{semantic.color.bg.brand.strongest.default}` | `var(--…)` | `--button-primary-color-bg-default: var(--color-bg-brand-strongest-default)` |
| 그림자 묶음 (`$type: shadow`) | `box-shadow` 값 하나 (속성 5개의 `var()`를 공백으로) | `--shadow-xsmall: var(--effect-offset-x-0) var(--effect-offset-y-1) var(--effect-blur-6) var(--effect-spread-0) var(--color-shadow-xsmall)` |

- 원본 치수는 모두 px 기준이다. rem은 사용자가 브라우저 글자 크기를 키웠을 때 글자와 간격이 함께 커지게 하려는 것이다.
- 참조는 원본에서 `{계층.경로}`(점으로 이음)다. CSS에서는 `var(--대상 CSS 이름)`이 된다.

## 4. 쓰는 법

- 제품 코드에서는 Semantic·Component 변수만 쓴다. Primitive(`--color-gray-600` 등)는 쓰지 않는다. 자동 검사가 필요하면 `tokens.css` 머리 주석의 Primitive 변수 이름 패턴을 쓸 수 있다.
- 컴포넌트를 만들 때는 그 컴포넌트의 Component 변수를 먼저 쓴다. 맞는 것이 없을 때만 Semantic을 쓰고, 없는 이름을 비슷한 이름으로 대신하지 않는다.
- 글자는 예외다. Component 글자 변수는 없다. `component-specs.json`의 `textStyles`가 대상마다 적은 Semantic 글자 스타일 변수 5개(`--font-label-14-400-size`·`-weight`·`-line-height`·`-letter-spacing`·`-family`)를 쓴다. 단축 변수(`--font-label-14-400`)에는 자간이 들어 있지 않으므로, 단축 변수를 쓸 때는 자간 변수도 함께 적용해야 디자인과 같다.
- 날짜·시간·수량처럼 자릿수가 바뀌어도 폭이 흔들리면 안 되는 숫자는 `textStyles`에 `fontVariantNumeric: tabular-nums`가 있다. 이 대상에는 `font-variant-numeric: tabular-nums`를 함께 적용한다(변수 없음. 피그마 텍스트 스타일 `label/[크기]/tabular/[굵기]`).
- `deprecated` 변수는 주석에 대체 변수가 있다. 새 코드에서 쓰지 않는다.
- 새 버전을 받으면 변경 이력(`02_CHANGELOG.md`)의 「삭제」「운영 출력 변경」에 코드 수정이 필요한 항목이 있다.

## 5. component-specs.json 읽는 법

컴포넌트마다 변형·사이즈·상태별로 어떤 CSS 속성에 어떤 변수를 쓰는지 적혀 있다.

| 키 | 내용 |
| --- | --- |
| `colors` | [변형][상태][대상][CSS 속성] → 변수 |
| `sizeTokens` | [사이즈][대상][CSS 속성] → 변수 |
| `common` | 변형·사이즈와 상관없이 공통으로 쓰는 변수 |
| `resolved` | [변형][상태][대상][CSS 속성]에 실제로 적용되는 최종 변수. 기본 → 기본+상태 → 변형 → 변형+상태 순으로 덮어쓴 결과 |
| `textStyles` | 대상별 글자 스타일(숫자 폭 고정 대상은 `fontVariantNumeric`) |
| `stateSelectors`, `variantSelectors` (파일 맨 위) | 상태·변형 이름 → CSS 선택자 |

- 대상 `root`는 컴포넌트 자신이다.
- 상태 변수가 있는 속성은 그 상태에서 상태 변수 값으로 바뀌고, `-default`만 있는 속성은 모든 상태에서 같은 값을 쓴다.
- `resolved`에는 덮어쓰기 순서까지 반영한 최종 변수가 적혀 있다.

## 6. 상태·변형 선택자

토큰 이름의 상태·변형 구간과 CSS 선택자의 권장 대응이다. `tokens.css`·`component-specs.json`도 이 대응을 기준으로 만들었다. 구현 방식(클래스, 컴포넌트 속성 등)은 개발 환경에 맞게 정하되, 상태·변형과 변수의 대응은 같아야 한다.

| 구간 | 선택자 |
| --- | --- |
| `default` | `(기본 선택자)` |
| `hover` | `:hover` |
| `pressed` | `:active` |
| `focus` | `:focus-within, :focus` |
| `disabled` | `:disabled, [aria-disabled="true"], [data-state="disabled"] (진행 막대)` |
| `readonly` | `[readonly], [aria-readonly="true"]` |
| `error` | `[aria-invalid="true"], [data-state="error"] (진행 막대·툴팁)` |
| `checked` | `:checked, [aria-checked="true"], [aria-checked="mixed"], :indeterminate` |
| `selected` | `[aria-selected="true"], [aria-pressed="true"]` |
| `required` | `[aria-required="true"]` |
| `attention` | `[data-attention="true"]` |
| `subtle` | `[data-emphasis="subtle"]` |
| `tone` | `[data-tone="<톤>"] (neutral, highlight, info, success, attention, warning, danger)` |
| `plain` | `[data-type="plain"]` |
| `adjacent` | `[data-adjacent="true"]` |
| `primary` | `[data-appearance="primary"]` |
| `secondary` | `[data-appearance="secondary"]` |
| `base` | `[data-appearance="base"]` |
| `accent` | `[data-appearance="accent"]` |
| `danger` | `[data-appearance="danger"]` |
| `filled` | `[data-type="filled"]` |
| `outlined` | `[data-type="outlined"]` |
| `rangeMiddle` | `[aria-selected="true"][data-range="middle"]` |
| `saturday` | `[data-day="saturday"]` |
| `sunday` | `[data-day="sunday"]` |
| `link` | `[data-position="link"]` |
| `upcoming` | `[data-status="upcoming"]` |
| `current` | `[aria-current="page"], [aria-current="step"]` |
| `completed` | `[data-status="completed"]` |

- `:disabled` 요소는 포커스를 받지 않는다. 피그마 컴포넌트의 `showFocus`처럼 비활성 상태에서도 키보드 포커스와 포커스 링이 필요하면 `disabled` 속성 대신 `aria-disabled="true"`를 쓰고 동작을 막는다. 선택자는 같은 `disabled` 구간에 대응한다.
- 입력 필드(`field-*` 색을 쓰는 textField·passwordField·textArea·select 등)는 `error`가 다른 상태와 겹칠 수 있다. `error`만 있으면 `-error` 값을 쓴다. `error` + `hover`·`focus`이면 바탕은 `-hover`·`-focus` 값을 쓰고, 테두리와 오류 링만 `-error` 값(`field-color-border-error`·`field-ring-color-border-error`)을 쓴다. `error` + `readonly`·`disabled`이면 오류를 표시하지 않고 그 상태 값만 쓴다. attention·required 변형(`field-attention-color-*`·`field-required-color-*`)도 같고, 셀렉트는 펼침(open)을 `focus`로 본다.
- 표 칸(`table-cell-*` 바탕을 쓰는 table-gridCell)은 바탕 색 하나만 바뀌므로 상태·변형이 겹치면 비활성(`disabled`), 오류(`error`), 선택(`selected`), 강조(`attention`), `hover`, 기본 순으로 앞의 것 하나만 쓴다. 예를 들어 오류 칸은 선택·hover여도 `table-cell-color-bg-error`, 선택된 칸은 hover여도 `table-selected-cell-color-bg-default`를 쓴다.

## 7. 원본 구조 (design-tokens.tokens.json)

- DTCG 형식의 중첩 구조다. `primitive`·`semantic`·`component` 아래에 이름 구간 하나가 키 하나다.
- 컴포넌트는 첫 구간(컴포넌트 이름) 아래에 있다. 여러 컴포넌트가 함께 쓰는 그룹(`button`, `field` 등)의 정보는 `component.$extensions["com.bss"].groups`에 있다.
- 토큰마다 값은 `$value`, 타입은 `$type`, 설명은 `$description`에 있다. CSS 이름·피그마 변수·상태는 `$extensions["com.bss"]`에 있다.
- 원본은 조회·변환용이다. 받은 원본을 고쳐 쓰지 않는다.

## 8. 문의·변경 요청

- 토큰 원본과 이름·값의 변경은 DS에서만 한다. 받은 파일을 고쳐 쓰면 다음 버전과 맞출 수 없게 되니, 필요한 변경은 DS에 요청한다.
- 없는 토큰이 필요하거나 이름·설명이 모호하면 컴포넌트 이름과 화면 예시를 함께 보내 준다.
