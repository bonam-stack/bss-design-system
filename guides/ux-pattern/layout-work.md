조회조건 → 상세정보 → 컨텐트 모듈로 이어지는 일반 업무 화면의 표준 수직 구조입니다.
대부분의 조회·처리 업무 화면이 이 틀을 공유합니다.

#### 개요 · 언제 쓰나요?

일반형 화면 구조는 데이터를 조회하고 그 결과를 다루는 업무 화면의 표준 틀입니다.
조회조건 → (상세정보) → 컨텐트 모듈 순의 적층형 구조를 따릅니다.

이 업무를 일반형으로 만들지 판정하는 기준은 [업무 화면 편성](work-composition.html)이 규정합니다.

###### ✓ 이럴 때 사용합니다

- 특정 요청에 대한 결과를 조회하거나, 조회 후 수정·삭제·신규 입력으로 이어지는 업무
- 절차가 필요 없다고 판정한 업무, 또는 정책적 이유로 노드형 화면을 쓸 수 없는 경우

###### ✕ 다른 레이아웃을 사용합니다

- 절차형으로 판정한 업무 화면 → [노드형 화면](layout-node.html)

#### 전체 구조

위→아래로 콘텍스트 바 → 페이지 타이틀 모듈 → (사용 안내) → 조회조건 → 상세정보 → (탭 모듈) → 컨텐트 모듈 순으로 쌓입니다.
사용 안내는 필요할 때만 두는 선택 모듈입니다.
이 문서는 영역의 자리와 순서, 화면 전체에 걸리는 원칙을 다룹니다.
각 모듈의 생김새는 [일반형 화면 모듈 개요](mod-general-overview.html)가 규정합니다.

1. 콘텍스트 바화면 맨 위, 페이지 타이틀 모듈 위에 놓입니다. 브레드크럼으로 현재 위치를 보여 줍니다.
2. 페이지 타이틀 모듈업무 명칭을 페이지 타이틀로 정의합니다.
3. 사용 안내 (콜아웃)화면 성격·주의사항을 페이지 타이틀 바로 아래에 안내하는 선택 모듈입니다.
4. 조회조건업무의 진행을 위해 필수적인 정보를 입력하는 영역입니다.
5. 상세정보조회 결과 중 마스터 성격의 데이터를 대표 정보 위주로 보여 줍니다.
6. 컨텐트 모듈실제 업무 컨텐트가 놓이는 가장 큰 영역입니다. 내부 구조는 [컨텐트 모듈 개요](layout-content.html)를 따릅니다.

#### 제목 원칙

화면의 제목은 페이지 타이틀 하나로 세우고, 그 아래로 제목을 늘리지 않습니다.

핵심 원칙페이지 타이틀은 그 화면이 무슨 업무인지 정확히 드러내야 합니다.
페이지 타이틀 아래의 서브 제목이나 각 모듈의 개별 타이틀은 원칙적으로 두지 않습니다.

- **페이지 타이틀 — 매우 명확·정확하게**: 화면의 업무를 한눈에 알 수 있는 정확한 명칭으로 세웁니다. (명칭 품질 기준은 [일반형 화면 모듈 개요](mod-general-overview.html)의 페이지 타이틀 모듈을 따릅니다.)
- **서브 제목 — 두지 않음**: 페이지 타이틀 아래 계층의 서브 제목은 두지 않습니다.
- **모듈 타이틀 — 두지 않음(조회조건 예외)**: 조회조건·상세정보·컨텐트 모듈 등 각 부의 개별 모듈 타이틀은 두지 않습니다. 단 [조회조건](search-conditions.html)만은 화면마다 같은 명칭으로 표기하는 예외입니다.
- **다단 예외 — 중간 선택 영역 타이틀**: 다단 구성에서 중간 단계의 선택 영역에는 무엇을 고르는 단계인지 알리기 위해 예외적으로 타이틀을 둘 수 있습니다.

#### 조회조건

화면 전체에 영향을 주는 공통 검색 요소를 결정하는 화면 최상단 모듈입니다.
여기서 정한 조건이 페이지 컨텐트 전체에 적용됩니다.

핵심 원칙입력 방식 · 1줄 배치 · 필수 표시 등 상세 규칙은 [조회조건 모듈](search-conditions.html) 문서에서 규정합니다.
전체 레이아웃 관점의 핵심 원칙만 아래에 둡니다.

- **화면 최상단 · 전체 적용**: 화면 최상단에 두며, 그 결과가 하단 컨텐트 전체에 적용됩니다. 특정 단일 테이블만 좁히는 조건은 여기 두지 않고 [상세검색](search-detail.html)으로 이관합니다.
- **'필수 조건'과 다름**: 조회조건은 '화면 전체에 영향을 주는 검색 요소'를 뜻합니다. 필수 여부는 별개이며, 페이지 로딩에 반드시 필요한 조건만 컨트롤 배경으로 구분합니다.
- **없으면 생략**: 화면 전체에 영향을 주는 검색 요소가 없으면 이 모듈을 생략합니다. (전체 데이터가 바로 노출되는 화면은 조회조건 없이 컨텐트 내 검색으로 운용합니다.)

#### 컨텐트 모듈

실제 업무 컨텐트가 놓이는 가장 큰 영역입니다.
검색·선택·처리 액션 · 결과 테이블 · 하단 상태(총 건수·페이지)가 이 자리에 통합되며, 화면(패턴)마다 이 영역만 달라집니다.

핵심 원칙컨텐트 유틸리티 · 데이터 테이블 · 상태바 등 컨텐트 모듈의 내부 구조와 세부 동작은 [컨텐트 모듈 개요](layout-content.html) 문서에서 규정합니다.
이 문서는 전체 화면 레이아웃 관점에서 컨텐트 모듈이 놓이는 위치만 다룹니다.

#### 스크롤 원칙

스크롤은 특정 영역이 아니라 전체 페이지를 기준으로 다룹니다.

핵심 원칙컨텐트 모듈은 상단 레이아웃·조회조건·상세정보 아래로 페이지 하단 전체를 차지하도록 설계됩니다.
기본 상태에서는 전체 구조가 한 화면(뷰포트)에 담겨 **페이지 세로 스크롤이 없고**, 넘치는 결과는 컨텐트 영역 내부에서 스크롤합니다.

- **기본 상태 — 페이지 스크롤 없음**: 컨텐트 모듈이 남은 세로 공간을 모두 채우고, 위쪽 모듈(상단 레이아웃·조회조건·상세정보)은 화면에 보이도록 유지합니다. 결과가 많을 때의 스크롤은 컨텐트 영역 내부로 한정합니다.
- **펼침 시 — 전체 페이지 세로 스크롤 발생**: 조회조건·상세정보가 펼쳐지면 그만큼 세로 공간을 차지해 아래 컨텐트 모듈이 밀려나고 전체 페이지에 세로 스크롤이 생깁니다. 이는 의도된 동작이며, 접으면 다시 한 화면에 맞습니다.
- **패턴 유형별 허용도**: 테이블 중심의 업무형 레이아웃에서는 스크롤을 최대한 자제하는 것을 기본으로 합니다. 반면 전체 화면 전환·리딩·상세 뷰처럼 흐름이 페이지 단위로 넘어가는 패턴에서는 가운데 영역의 스크롤을 넓게 인정합니다. (→ [전체 화면 전환](view-transitions.html))

#### 실제 예시

실제 화면입니다.
전체 구조를 비율을 축소해 보여 줍니다.
조회조건·상세정보의 펼치기를 눌러 동작을 확인할 수 있으며, 컨텐트 모듈은 자리표시입니다.

일반형 화면 구조 · 표준 화면새 탭에서 크게 보기※ 예시 이미지 — 레이아웃/디자인은 확정 아님. 패턴 구조만 참고.
#### Do / Don't

###### Do · 이렇게 합니다

- 조회조건 → 상세정보 → 컨텐트 모듈 순의 수직 구조를 유지합니다.
- 필수 조건은 첫 줄에, 추가 조건·상세정보는 기본 접힘으로 둡니다.
- 컨텐트 모듈의 내부 구성은 [컨텐트 모듈 개요](layout-content.html)를 따릅니다.

###### Don't · 이건 피합니다

- 영역 순서를 화면마다 임의로 바꾸지 않습니다.
- 페이지 타이틀 외에 서브 제목이나 모듈별 타이틀을 만들지 않습니다. (조회조건·다단 중간 선택 영역은 예외)
- 단일 테이블 전용 조건을 조회조건에 섞지 않습니다.
- 조회조건을 '필수 조건'과 같은 뜻으로 다루지 않습니다. (필수 여부는 조건별 표시로 구분합니다)
- 상세정보·추가 조회조건을 기본 펼침으로 로딩해 첫 화면을 복잡하게 만들지 않습니다.
