화면을 막지 않고 알리는 메시지입니다.
 한 줄로 알리고 끝나면 토스트, 처리 현황과 후속 동작이 필요하면 스낵바를 씁니다.
 시스템 전역 · 업무환경 메시지는 화면 상단의 스트라이프로 알립니다. (일반 UI · 노드 UI 공통)

#### 개요 · 언제 쓰나요?

| 수단 | 사용 시점 | 담는 것 | 사라지는 방식 |
| --- | --- | --- | --- |
| 토스트 | 결과만 알리고 개입이 필요 없을 때 | 메시지 한 줄 | 4초 후 저절로 |
| 스낵바 | 처리 현황이나 후속 동작이 필요할 때 | 제목 + 처리 현황 + 액션 1개 | Normal은 8초 후 저절로 · Action은 × 로 닫습니다 |
| 확인·경고 다이얼로그 | 실행하기 전에 의사를 물어야 할 때 | 질문 + 취소·실행 | 버튼 선택으로 |
| 스트라이프 | 시스템 전역 · 업무환경을 알릴 때 | 메시지 한 줄 | 고정형은 × 로 닫을 때까지 · 삭제형은 4초 후 저절로 |

**한 줄 판단**: 알리고 끝나면 토스트 · 후속 동작이 필요하면 스낵바 · 실행 전에 물어야 하면 [확인·경고 다이얼로그](resp-dialog.html)입니다.

시스템 전역 · 업무환경 메시지는 아래 스트라이프 절이 다룹니다.

##### 되돌릴 수 있습니까

이 질문 하나가 실행 전과 실행 후를 모두 정합니다.

| 동작 | 실행 전 | 실행 후 |
| --- | --- | --- |
| 되돌릴 수 있습니다 | 묻지 않고 바로 실행합니다 | 스낵바로 알리고 실행 취소를 함께 줍니다 |
| 되돌릴 수 없습니다 | 확인·경고 다이얼로그로 묻습니다 | 토스트로 결과를 알립니다 |
| 실패했습니다 | 해당 없습니다 | 자동으로 사라지는 알림에 담지 않습니다 |

###### ✓ 이럴 때 사용합니다

- 저장·전송처럼 성공한 결과를 짧게 알릴 때 → 토스트
- 시간이 걸리는 처리를 시작했다고 알릴 때 → 토스트
- 건수가 갈리는 결과를 알릴 때 → 스낵바
- 되돌릴 수 있는 변경에 되돌릴 기회를 줄 때 → 스낵바
- 시스템 점검 · 장애처럼 업무환경을 알릴 때 → 스트라이프

###### ✕ 다른 패턴을 사용합니다

- 실행 전에 의사를 물어야 할 때 → [확인·경고 다이얼로그](resp-dialog.html)
- 처리가 실패했을 때 → [확인·경고 다이얼로그](resp-dialog.html)
- 입력값 검증 실패 → [폼 유효성 체크](resp-form-validation.html)
- 세션 만료·권한 없음 → [전역 예외 화면](resp-error-page.html)

핵심 원칙토스트와 스낵바는 알리기만 합니다.
 둘 다 시간이 지나면 사라지므로, 사라져도 괜찮은 내용만 담습니다.

#### 구성요소

스낵바가 네 부분을 모두 가진 가장 큰 형태이고, 토스트는 여기서 한 줄만 남은 축소형입니다.

1. 제목무슨 처리의 결과인지 한 줄로 적습니다. 스낵바에는 반드시 둡니다.
2. 처리 현황건수를 항목별로 적습니다. 숫자는 성격에 따라 색이 갈립니다. → 신청 · 정상처리 · 오류
3. 액션아웃라인 버튼 하나입니다. ‘실행 취소’처럼 결과에서 바로 이어지는 동작만 담습니다.
4. 닫기직접 닫는 수단입니다. 액션이 있는 스낵바(Action)에만 둡니다.

#### 핵심 동작 · 상태

##### 토스트와 스낵바의 유형

토스트는 알리는 상태에 따라, 스낵바는 담는 내용에 따라 갈립니다.

| 수단 | 유형 | 쓰임 | 예 | 채택 |
| --- | --- | --- | --- | --- |
| 토스트 | 정보 Basic | 안내하거나 진행을 시작했을 때 | 내려받기를 시작했습니다 | 씁니다 |
| 토스트 | 성공 Success | 저장·전송이 끝났을 때 | 완료했습니다 | 씁니다 |
| 토스트 | 경고 Warning | 다 하지는 못했지만 더 할 일이 없을 때 | 이미 적용된 00건은 제외했습니다 | 씁니다 |
| 토스트 | 실패 Error | 처리가 실패했을 때 | 오류가 발생했습니다 | **지양합니다** |
| 스낵바 | Normal | 제목과 설명만 알릴 때 | 요금제 이용 현황 | 씁니다 |
| 스낵바 | Action | 처리 현황과 후속 동작이 필요할 때 | 전건 성공은 실행 취소 · 부분 실패는 오류 내역 보기 | 씁니다 |

토스트는 바탕색이 전 유형 같고 아이콘만 갈립니다.
 아이콘은 모양까지 갈라 둡니다.
→ 성공은 원 · 경고는 삼각형
 색으로만 구분하면 색약 사용자에게 유형이 전달되지 않습니다.

경고와 실패의 경계는 후속 조치입니다.
 결과를 알아 두면 끝나는 것은 경고, 사용자가 다시 손을 써야 하는 것은 실패입니다.

스낵바 Action은 담는 결과에 따라 액션이 갈립니다.
 전건 성공이면 ‘실행 취소’, 오류가 1건이라도 있으면 ‘오류 내역 보기’입니다.
 원인을 모르는 상태에서 되돌릴 수는 없으므로 오류 내역 확인이 앞섭니다.

##### 표시 규칙

| 항목 | 토스트 | 스낵바 |
| --- | --- | --- |
| 위치 | 콘텐트(본문) 영역 하단 중앙 | 같습니다 |
| 폭 | 문구 길이에 따라 늘어나지 않습니다 | 고정입니다 |
| 노출 시간 | 4초 | Normal은 8초 · Action은 정하지 않습니다 |
| 마우스 올림 | 시간을 멈추고 유지합니다. 벗어나면 다시 셉니다 | Normal은 같습니다 |
| 선행 아이콘 | 상태에 따라 둡니다 | 두지 않습니다 |
| 닫기 버튼 | 두지 않습니다 | Action만 × 를 둡니다 |
| 액션 버튼 | 두지 않습니다 | 1개까지 |
| 액션 우선순위 | 해당 없습니다 | 오류가 1건이라도 있으면 오류 내역 보기가 실행 취소보다 앞섭니다 |
| 동시 표시 | 하나만 띄웁니다. 새 알림이 직전 것을 대체합니다 | 같습니다 |
| 화면 밀림 | 본문 위에 떠 있으므로 레이아웃을 밀지 않습니다 | 같습니다 |
| 사이드 패널이 열렸을 때 | 본문 중앙을 유지합니다. 패널 쪽으로 밀지 않습니다 | 같습니다 |
| 다이얼로그와 겹침 | 다이얼로그가 열려 있는 동안에는 띄우지 않습니다 | 같습니다 |
| 읽어 주기 | 상태 알림(role="status")으로 알리며 작업을 끊지 않습니다 | 같습니다 |

기준은 뷰포트가 아니라 본문입니다.
 사이드 내비게이션 바나 AI Communicator가 열리고 닫히면 본문 폭이 바뀌므로, 그때마다 다시 계산합니다.

사이드 패널은 다시 계산하지 않습니다.
 사이드 내비게이션 바·AI Communicator는 본문 폭을 줄이지만, 사이드 패널은 본문 위에 겹치는 층이라 본문 폭을 바꾸지 않습니다([레이어 구조](layout-layer.html)).
 기준이 그대로이므로 토스트도 그대로 둡니다.
 노드 UI는 액션바가 같은 상황에서 밀리므로 거동이 다릅니다.
아래 노드 UI 절에서 다룹니다.

치수·색·타이포는 디자인 가이드의 Toast · Snackbar 컴포넌트가 소유합니다.
 목업에 적힌 수치는 그 실측을 옮긴 표기이며 이 문서가 정하는 규정이 아닙니다.

##### 다이얼로그와의 관계

한 동작에 둘 다 나오는 것은 정상입니다.
 확인 다이얼로그 → 실행 → 토스트 순으로, 묻는 자리와 알리는 자리가 다릅니다.

되돌릴 수 있는 동작에 확인을 붙이면 문구를 읽지 않고 누르는 습관이 생깁니다.
 그래서 되돌릴 수 있으면 묻지 않고 실행한 뒤 스낵바로 되돌릴 기회를 줍니다.

##### 실패는 어떻게 알립니까

실패는 사라진 뒤에 다시 볼 방법이 없고, 원인과 다음 행동을 한 줄에 담을 수 없습니다.

| 실패의 종류 | 어디가 받습니까 |
| --- | --- |
| 입력값이 규칙에 맞지 않습니다 | [폼 유효성 체크](resp-form-validation.html) |
| 처리가 실패했습니다 | [확인·경고 다이얼로그](resp-dialog.html) |
| 일부만 실패했습니다 | 스낵바 · 오류 건수 + 오류 내역 보기 |
| 세션이 끊기거나 권한이 없습니다 | [전역 예외 화면](resp-error-page.html) |

그래서 실패를 자동으로 사라지는 알림에 단독으로 담는 것은 지양합니다.

스낵바가 담는 오류 건수는 예외이지만, 스낵바도 닫으면 사라집니다.
 그래서 ‘오류 내역 보기’는 유일한 경로가 될 수 없습니다.
 오류 내역은 스낵바가 사라진 뒤에도 처리 결과 화면이나 이력에서 다시 열 수 있게 둡니다.

#### 스트라이프

스트라이프는 시스템 전역 · 업무환경에 관한 메시지를 화면 상단 콘텍스트 바 가운데에 띄웁니다.
 일반 UI와 노드 UI에 똑같이 뜹니다.
 무엇을 띄울지는 [전역 예외 화면](resp-error-page.html)의 스트라이프 기준을 따릅니다.

| 항목 | 고정형 | 삭제형 |
| --- | --- | --- |
| 쓰임 | 계속 보여야 하는 메시지 | 잠시 알리면 되는 메시지 |
| 위치 | GNB 아래 [콘텍스트 바](mod-general-overview.html) 가운데, 폭을 줄여 겹쳐 뜹니다 | 같습니다 |
| 닫기 버튼 | × 를 둡니다 | 두지 않습니다 |
| 사라지는 방식 | × 를 눌러 닫을 때까지 남습니다 | 4초 후 저절로 사라집니다 |

고정형의 × 는 닫는 유일한 방법입니다.
 스낵바의 × 처럼 시간이 지나기 전에 미리 닫는 수단이 아니므로, 고정형에는 시간을 두지 않습니다.

- **업무처리 결과는 띄우지 않습니다**: 사용자가 한 처리의 결과는 토스트 · 스낵바가 받습니다.
- **콘텍스트 바를 잠시 덮습니다**: 스트라이프가 사라지면 원래 상태로 돌아옵니다.
- **여러 개가 함께 생기면 긴급한 것을 먼저 보여 줍니다**: 오류 · 차단(Red) → 확인 필요(Orange) → 사전 경고(Yellow) → 안내 · 진행(Blue) 순입니다. 긴급도가 같으면 새 것을 쌓아 보여 줍니다.
- **컬러는 상태를 따릅니다**: [피드백 체계](msg-system.html)의 상태별 컬러를 씁니다. (예. 점검 예정 → 사전 경고 Yellow)

#### 실제 예시

행을 선택하고 아래 세 버튼을 눌러 흐름을 확인합니다.

1. **보관 처리** → 스낵바 · ‘실행 취소’
2. **일괄 적용** → 경고 토스트
3. **선택 삭제** → 위험 다이얼로그 → 실행 → 성공 토스트

마우스를 올려 시간이 멈추는지, 연달아 띄우면 하나만 남는지, 사이드 내비게이션 바를 접으면 알림이 따라 옮겨 가는지도 함께 확인합니다.

행을 선택한 뒤 보관 처리 · 일괄 적용 · 선택 삭제를 눌러 스낵바와 토스트를 차례로 확인합니다.

토스트·스낵바 · 세 흐름 확인새 탭에서 크게 보기※ 예시 이미지 — 레이아웃/디자인은 확정 아님. 패턴 구조만 참고.
#### Do / Don't

###### Do · 이렇게 합니다

- 성공·완료는 토스트로 짧게 알립니다.
- 건수가 갈리는 결과는 스낵바로 처리 현황까지 보여 줍니다.
- 되돌릴 수 있는 변경에는 ‘실행 취소’를 함께 줍니다.
- 오류가 섞인 결과에는 ‘실행 취소’ 대신 ‘오류 내역 보기’를 줍니다.
- 되돌릴 수 없는 동작은 실행 전에 묻고, 실행 후에 알립니다.
- 위치와 폭을 화면마다 같게 둡니다.

###### Don't · 이건 피합니다

- 실패를 자동으로 사라지는 알림에 단독으로 담지 않습니다.
- 실패 건수를 경고 토스트에 담지 않습니다.
- ‘오류 내역 보기’를 오류를 확인하는 유일한 경로로 두지 않습니다.
- 버튼을 두 개 이상 넣지 않습니다.
- 여러 개를 겹쳐 쌓지 않습니다.
- ‘성공적으로’처럼 상투적인 문구를 쓰지 않습니다.

노드 캔버스에서 화면을 막지 않고 처리 결과를 알리는 알림입니다.
 노드 UI에는 토스트만 있고, 스낵바가 받던 자리는 노드 안 결과 배너가 가져갑니다.

#### 개요 · 언제 쓰나요?

**한 줄 판단**: 사라져도 되는 한 줄이면 토스트 · 노드에 남아야 하면 결과 배너 · 지금 무엇을 하라는 지시면 액션바 안내 문구입니다.

노드 UI에는 알리는 자리가 셋입니다.
 그래서 토스트를 쓸지 판단하기 전에 세 자리 중 어디가 받을 내용인지를 먼저 가릅니다.

| 자리 | 무엇을 받습니까 | 얼마나 남습니까 |
| --- | --- | --- |
| 액션바 안내 문구 | 지금 무엇을 하라는 지시 | 노드가 바뀔 때까지 |
| 노드 안 결과 배너 | 그 노드 처리의 결과 · 사유 · 건수 | 노드에 남습니다 |
| 토스트 | 노드를 넘기지 않는 보조 동작의 결과 | 4초 후 사라집니다 |

###### ✓ 이럴 때 사용합니다

- 보조 동작이 끝났을 때 → 인증번호 발송 · 안내 SMS 전송
- 사이드 패널이나 모달에서 저장 · 추가 · 수정을 마쳤을 때
- 후속 업무를 생성했을 때

###### ✕ 다른 패턴을 사용합니다

- 그 노드 처리의 결과 · 사유 · 건수 → 노드 안 결과 배너
- 입력값이 규칙에 맞지 않을 때 → [폼 유효성 체크](resp-form-validation.html)의 노드 UI 탭
- 그 단계의 처리가 실패했을 때 → [전역 예외 화면](resp-error-page.html)의 노드 UI 탭
- 실행 전에 의사를 물어야 할 때 → [확인·경고 다이얼로그](resp-dialog.html)

핵심 원칙사라져도 되는 것만 토스트에 담습니다.
 노드에 남아야 하는 것은 노드 안 결과 배너가 받습니다.

#### 구성요소

노드 UI 토스트는 메시지 한 줄입니다.
 그래서 구성요소는 토스트 자체보다 그것이 놓이는 자리와 띄우는 자리로 읽습니다.

1. 토스트노드를 넘기지 않는 보조 동작의 결과입니다. 액션바 위에 뜨고 4초 뒤 사라집니다.
2. 액션바 안내 문구지금 무엇을 하라는 지시입니다. 결과 통지 자리가 아니며 노드가 바뀔 때까지 남습니다.
3. 보조 버튼토스트를 띄우는 자리입니다. 단계는 넘어가지 않고 노드도 그대로 있습니다.

유의사항노드 안 결과 배너의 규격은 이 문서가 정하지 않습니다.
 이 문서는 토스트가 받지 않는 것이 어디로 가는지까지만 말합니다.

#### 핵심 동작 · 상태

##### 스낵바는 어디로 갔습니까

노드 UI에는 스낵바를 두지 않습니다.
 스낵바가 담던 두 가지가 각각 다른 자리로 갑니다.

- 처리 현황과 건수는 노드 안 결과 배너가 받습니다. → 배너는 노드에 남으므로 사라지기 전에 읽어야 할 이유가 없습니다.
- 되돌리기는 완료 노드의 ‘수정’으로 갈음합니다. → 되돌리는 절차는 [역방향 진행](node-flow-reverse.html)에서 설명합니다.

그래서 일반 UI 탭의 되돌릴 수 있습니까 표는 노드 UI에 그대로 걸리지 않습니다.
 되돌릴 수 있는 동작이어도 스낵바로 실행 취소를 주지 않습니다.

##### 세 자리 중 무엇이 받습니까

사라져도 되는지가 자리를 정합니다.

- 노드의 결과는 배너가 받아 노드에 남습니다. → 그 노드를 나중에 다시 볼 때도 무엇이 처리됐는지 읽을 수 있어야 하므로, 사라지는 알림에 담지 않습니다.
- 그 결과에서 갈라져 나온 보조 동작은 토스트가 받아 사라집니다. → 후속 업무를 생성했다는 사실은 생성된 업무 자체가 증거이므로, 알림이 사라져도 잃을 것이 없습니다.
- 노드를 넘기는 결과는 토스트가 받지 않습니다. → 단계가 넘어갔다는 것은 노드 상태와 액션바가 이미 말합니다. 토스트를 겹치면 같은 것을 두 번 알립니다.
- 액션바 안내 문구 자리에 결과를 넣지 않습니다. → 다음에 무엇을 할지 읽는 자리라 결과가 들어오면 지시가 밀립니다.

##### 어디에 뜹니까

기준은 뷰포트가 아니라 캔버스입니다.
 캔버스 하단 중앙은 액션바가 이미 쓰고 있으므로, 토스트는 액션바를 기준으로 그 위에 놓습니다.

| 항목 | 노드 UI |
| --- | --- |
| 자리 | 캔버스 하단 중앙 · 액션바 바로 위 |
| 액션바가 움직일 때 | 같은 값만큼 함께 움직입니다 |
| 고객정보 위젯을 펼쳤을 때 | 액션바 · 범례와 함께 올라갑니다 |
| 사이드 패널이 열렸을 때 | 액션바가 남은 폭의 중앙으로 밀리므로 함께 밀립니다 |

기준을 캔버스로 두는 이유는 일반 UI에서 기준을 본문으로 두는 것과 같습니다.
 노드 UI의 본문이 캔버스입니다.

캔버스 안 요소의 좌표와 거동은 [노드형 화면](layout-node.html)이 규정합니다.
 토스트는 그 좌표를 따라가는 쪽입니다.

##### 사이드 패널이나 모달을 닫을 때

닫힘 자체가 결과 통지입니다.

- 패널이 사라지고 노드 값이 바뀐 것이 이미 보이므로 토스트는 한 줄만 얹습니다. → 무엇이 어떻게 바뀌었는지 다시 늘어놓지 않습니다.
- 저장하지 못했을 때는 패널을 닫지 않습니다. → 닫고 토스트로 실패를 알리면 고치러 돌아갈 자리가 사라집니다. 패널 안에서 알립니다.
- 계산기나 테이블 전체보기 같은 모달도 같습니다. → 닫힘이 결과를 말하는 구조가 같으므로 규칙을 따로 두지 않습니다.

##### 유형은 하나입니다

노드 UI 토스트는 Success 하나로 수렴하므로 선행 아이콘을 둡니다.

- Basic이 설 자리가 없습니다. → 진행이 시작됐다는 것은 노드 상태와 액션바가 알립니다.
- Warning과 Error는 다른 자리가 받습니다. → 그래서 아이콘 모양으로 유형을 가를 대상이 없습니다.

일반 UI 탭의 유형 표는 유형이 넷일 때의 규정입니다.
 노드 UI에서는 그중 Success만 씁니다.

##### 실패는 어떻게 알립니까

실패는 사라진 뒤에 다시 볼 방법이 없으므로 토스트에 담지 않습니다.

| 실패의 종류 | 어디가 받습니까 |
| --- | --- |
| 입력값이 규칙에 맞지 않습니다 | [폼 유효성 체크](resp-form-validation.html)의 노드 UI 탭 |
| 업무 규칙상 진행할 수 없습니다 | 노드 안 결과 배너 |
| 그 단계의 처리가 실패했습니다 | [전역 예외 화면](resp-error-page.html)의 노드 UI 탭 |
| 세션이 끊기거나 권한이 없습니다 | [전역 예외 화면](resp-error-page.html) |

##### 일반 UI 탭과 같은 것

아래는 노드 UI에서도 같으므로 일반 UI 탭이 규정합니다.

| 무엇 | 어디에 |
| --- | --- |
| 치수 · 색 · 타이포의 소유 | 일반 UI 탭 · 표시 규칙 |
| 노출 시간과 마우스 올림 시 멈춤 | 일반 UI 탭 · 표시 규칙 |
| 동시에 하나만 띄우는 규칙 | 일반 UI 탭 · 표시 규칙 |
| 읽어 주는 방식 | 일반 UI 탭 · 표시 규칙 |
| 다이얼로그가 열려 있는 동안 띄우지 않는 것 | 일반 UI 탭 · 표시 규칙 |
| 메시지 문체 | 일반 UI 탭 · Do / Don't |
| 스트라이프 | 일반 UI 탭 · 스트라이프 |

#### 실제 예시

이 탭에는 눌러 보는 예시 화면을 두지 않습니다.
 위 **핵심 동작 · 상태**에 넣은 국면 화면이 예시를 겸합니다.
 확인할 곳은 자리 · 분담 · 좌표 · 패널 · 담지 않는 것 다섯 가지입니다.

#### Do / Don't

###### Do · 이렇게 합니다

- 보조 동작의 결과는 토스트로 한 줄만 알립니다.
- 노드에 남아야 하는 결과는 노드 안 결과 배너에 둡니다.
- 토스트를 액션바 위에 놓고, 액션바가 움직이면 함께 움직입니다.
- 사이드 패널과 모달은 저장에 성공했을 때만 닫고 토스트를 얹습니다.
- 노드 UI 토스트에는 선행 아이콘을 둡니다.
- 후속 업무를 만들었을 때는 만들었다는 사실만 알립니다.

###### Don't · 이건 피합니다

- 노드 UI에 스낵바를 두지 않습니다.
- 단계가 넘어갔다는 것을 토스트로 겹쳐 알리지 않습니다.
- 노드 처리의 결과 · 사유 · 건수를 토스트에 담지 않습니다.
- 액션바 안내 문구 자리에 결과를 넣지 않습니다.
- 저장하지 못한 사이드 패널을 닫고 토스트로 알리지 않습니다.
- 토스트를 뷰포트 기준으로 고정하지 않습니다.
