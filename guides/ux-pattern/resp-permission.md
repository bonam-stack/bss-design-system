권한이 없는 기능과 페이지를 어떻게 구분해 보이고, 어떻게 요청하게 할지를 규정합니다.
화면 전체가 막힌 경우의 화면 규격은 [전역 예외 화면](resp-error-page.html)이 규정합니다.

#### 개요 · 언제 쓰나요?

같은 화면이라도 사용자의 권한에 따라 쓸 수 있는 기능이 달라집니다.
지금은 요소마다 처리가 제각각이라, 어떤 메뉴는 아예 사라지고 어떤 버튼은 눌러야 막힌 것을 알게 됩니다.

이 문서는 세 자리를 나누어 규정합니다.
UI 요소 하나가 막힐 때, 메뉴·검색에서 페이지가 막힐 때, 노드에서 막힐 때입니다.
어느 자리든 판단은 하나로 시작합니다.
우회하는 수단이 없다면 노출하지 않습니다.

###### ✓ 이럴 때 사용합니다

- 권한에 따라 버튼·링크·행 액션·탭의 사용 여부가 달라지는 경우
- 권한에 따라 메뉴·검색 결과의 페이지 노출이 달라지는 경우
- 권한이 없는 기능을 사용자에게 알리고 요청받게 하는 경우
- 접속망이나 추가 인증 때문에 기능을 쓸 수 없는 경우

###### ✕ 다른 패턴을 사용합니다

- 권한 없음 화면의 규격 → [전역 예외 화면](resp-error-page.html)
- 권한과 무관하게 조건이 갖춰지지 않아 못 누르는 버튼 → [버튼 구조 및 동작](layout-action.html)
- 업무 사이를 잇는 규격 → [업무 연결](work-connect.html)
- 노드를 진행하다 권한으로 막힐 때 → [오류처리](node-flow-fail.html)

#### UI 요소의 권한 표기

- 권한 요청 등 권한이 제한된 상황을 우회하는 수단이 없다면 노출하지 않습니다.
- 다만 예외적으로 노출이 필요하거나 권한 문제를 해결할 방안이 있다면, 그 요소들은 아래 원칙으로 노출합니다.
- 권한이 막힌 버튼·링크는 잠금 아이콘으로 표기하고 비활성 상태로 둡니다. → 라벨과 링크 텍스트는 원래 규정된 내용을 그대로 쓰고, 여는 방식 아이콘 자리를 잠금 아이콘이 대신합니다.
- 마우스를 올리면 툴팁으로 권한이 없음을 알리고, 이어서 취할 액션을 함께 답니다. → ‘권한 요청’을 기본으로 두고, 목적에 따라 ‘업무 이관’ 같은 우회 기능을 더할 수 있습니다.

##### 버튼 유형

- 삭제처럼 파괴 행동은 잠긴 상태에서도 오류 색을 유지합니다. → 무슨 행동인지 색으로도 읽혀야 합니다.

버튼에 마우스를 올려 툴팁을 봅니다

##### 링크 유형

값에 마우스를 올려 툴팁을 봅니다

##### 테이블 행 액션 유형

- 액션이 하나뿐인 행은 행 클릭에 그 액션이 자동으로 부여됩니다. → 그래서 버튼이 아니라 행에 마우스를 올려도 버튼에 올린 것과 같은 효과를 줍니다. 잠금 안내 툴팁도 행 어디에서나 뜹니다.

행과 액션 아이콘에 각각 마우스를 올려 봅니다

##### 탭 유형

잠긴 탭에 마우스를 올려 툴팁을 봅니다

#### 사이드 내비게이션 바 메뉴 및 검색에서의 페이지 권한 표기

- 권한을 얻거나 우회할 수단이 없다면 노출하지 않습니다.
- 페이지에는 이 기준을 버튼·링크보다 엄하게 적용합니다. → 메뉴가 길어질수록 무엇이 내 일인지 흐려집니다.
- 노출하지 않기로 했으면 사이드 내비게이션 바와 검색 결과 양쪽에서 뺍니다. → 한쪽에만 남으면 눌러서 막히는 경험이 됩니다. 하위 항목이 모두 숨김이면 상위 그룹도 함께 숨깁니다.

##### 노출 방식

- 권한이 없는 메뉴와 검색 결과는 비활성 상태로 노출합니다.
- 즐겨찾기 등록 아이콘을 뺀 나머지 부가 속성은 권한 아이콘으로 대체합니다. → 인증 필요 같은 속성보다 권한 없음이 앞섭니다.
- 메뉴명에 마우스를 올리면 툴팁으로 권한 요청 등 관련 업무를 잇습니다. → UI 요소와 같은 방식입니다.
- 권한을 신청한 메뉴는 오른쪽에 별도 안내를 답니다. → UI 요소보다 공간에 여유가 있어 툴팁을 열지 않아도 읽힙니다.
- 그 밖의 기능은 기존 메뉴·검색 결과의 동작을 그대로 씁니다.

메뉴명과 ⓘ에 각각 마우스를 올려 봅니다

##### 화면 전체가 막힐 때

URL 직접 이동·Cross-linking처럼 메뉴와 검색을 거치지 않고 진입하는 경로가 남습니다.
이때는 페이지 안에서 권한 오류를 표기하며, 화면 규격은 [전역 예외 화면](resp-error-page.html)을 따릅니다.
복구 CTA는 권한 상태에 따라 달라집니다.

전역 예외 화면 규정에서 빠져 있는 상세 패턴을 더한 예제입니다

#### 접속망 · 인증으로 막힐 때

권한과 별개로, 지금 접속한 망이나 인증 상태 때문에 기능을 쓸 수 없는 경우가 있습니다. (로그인) 표기는 「UI 요소의 권한 표기」와 같고, 툴팁과 이어지는 행동만 다릅니다.

| 원인 | 툴팁 | 이어지는 행동 |
| --- | --- | --- |
| 권한 없음 | 권한이 없다고 알립니다 | 권한 요청 등 |
| 추가 인증 필요 | ‘추가 인증이 필요합니다’ | 누르면 그 자리에서 인증하고 원래 동작으로 돌아갑니다 |
| 접속망 제한 | ‘내부망에서만 사용할 수 있습니다’ | 없음 |

- **접속망으로 막힌 기능은 노출합니다**: 내부망에서는 쓸 수 있다는 사실이 해결 방안이기 때문입니다. 숨기면 기능이 없는 줄 알게 됩니다.
- **접속망 제한에는 권한 요청을 두지 않습니다**: 권한을 받아도 지금 접속에서는 쓸 수 없습니다.
- **추가 인증이 필요한 요소는 누를 수 있게 둡니다**: 잠금 아이콘은 달되 비활성으로 두지 않습니다.
- **메뉴 · 검색도 같은 원칙을 따릅니다**: 접속망으로 막힌 메뉴는 숨기지 않고 비활성으로 노출합니다.

#### 노드의 권한 표기

노드 업무 화면은 막힌 범위로 갈립니다.

| 어디가 막혔습니까 | 무엇이 규정합니까 |
| --- | --- |
| 화면 전체를 열 수 없습니다 | [전역 예외 화면](resp-error-page.html) |
| 화면은 열리고 노드 하나가 막혔습니다 | [오류처리](node-flow-fail.html)의 「권한으로 중단될 때」 |
| 노드가 아닌 요소(버튼·링크·탭)가 막혔습니다 | 이 문서의 「UI 요소의 권한 표기」 |

- 권한이 없는 노드는 잠금 아이콘·비활성으로 표기하지 않습니다. → 원래 내용을 감추고 완결형 컴포넌트로 바꿔 그 자리에서 불가 결과를 알립니다.
- 권한 요청·이관은 툴팁이 아니라 완결형 컴포넌트의 다음 조치 버튼으로 제공합니다. → 조치 배열과 승인 뒤 갱신은 [오류처리](node-flow-fail.html)가 규정합니다.
- 권한이 없는 노드가 편성돼 있으면 업무를 시작할 때 앞 노드를 진행하지 않고 그 노드로 먼저 이동합니다.

#### Do / Don't

###### Do · 이렇게 합니다

- 우회하는 수단이 없는 기능은 노출하지 않습니다.
- 노출한 기능은 잠금 아이콘으로 누르기 전에 구분되게 합니다.
- 라벨과 링크 텍스트는 원래 규정된 내용을 그대로 씁니다.
- 툴팁에 권한 요청을 기본으로 두고, 필요하면 우회 기능을 함께 답니다.
- 액션이 하나뿐인 행은 행에 마우스를 올려도 버튼과 같은 효과를 줍니다.
- 막힌 메뉴에도 메뉴 설명은 그대로 답니다.
- 권한이 없는 노드는 완결형 컴포넌트로 바꿔 그 자리에서 조치를 줍니다.

###### Don't · 이건 피합니다

- 아이콘 없이 비활성만으로 권한 문제를 표시하지 않습니다.
- 라벨을 ‘권한 없음’ 같은 말로 바꾸지 않습니다.
- 툴팁에 ‘눌러서 권한 요청’처럼 행동을 문구로 설명하지 않습니다.
- 진행할 수단이 없는데 요청 버튼을 두지 않습니다.
- 잠금 아이콘과 여는 방식 아이콘을 함께 달지 않습니다.
- 메뉴에서 숨긴 업무를 검색 결과에 남기지 않습니다.
- 노드를 잠금 아이콘·비활성으로 막지 않습니다.
