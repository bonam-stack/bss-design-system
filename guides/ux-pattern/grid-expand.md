목록의 행을 클릭하면 그 아래로 상세 영역이 아코디언처럼 펼쳐져, 화면 이동 없이 같은 자리에서 상세를 확인·편집하는 Master-Detail 표 패턴입니다.
목록의 맥락을 유지한 채 상세로 자연스럽게 이어지는 것이 이 패턴의 핵심입니다.

#### 개요 · 언제 쓰나요?

행확장 편집은 [일반목록](grid-board.html)의 확장형입니다.
행을 클릭(또는 좌측 ▶ 아이콘)하면 그 행 아래로 상세 영역이 펼쳐져, 화면을 옮기거나 창을 띄우지 않고 같은 자리에서 상세를 확인하고 간단히 편집합니다.
목록과 상세가 한 화면에 이어져 있어 맥락이 끊기지 않습니다.

핵심 원칙상세 업무는 사이드 패널·팝업으로도 할 수 있지만, 행확장 편집은 목록 맥락을 지키며 제자리에서 상세를 다루는 방식입니다.
목록의 위치·스크롤을 그대로 둔 채 행만 펼쳐, 상세를 보고 닫으면 곧바로 목록 흐름으로 복귀합니다.
콘텍스트 연결이 매끄러운 패턴입니다.

###### ✓ 이럴 때 사용합니다

- Master-Detail 구조에서 화면 이동 없이 상세를 확인·편집할 때
- 칼럼이 많아 한 행에 다 담기 어렵거나, 상세를 좌우로 넓게 펼쳐 보여야 할 때
- 조회·편집할 상세 정보가 단순할 때 (예. 주문 → 상세, 청구서 → 청구 항목)
- 클릭 흐름을 한 단계 더 늘리고 싶을 때 (아래 상세 표현 방식 참조)

###### ✕ 다른 패턴을 사용합니다

- 상세가 세로로 길거나 복잡해 스크롤이 필요할 때 → [사이드 패널](option-panel.html) · 팝업 · 풀페이지
- 여러 상세를 동시에 나란히 놓고 비교해야 할 때 → 다단 구성

#### 상세 표현 방식

행을 클릭해 상세를 다루는 방법은 여럿입니다([사이드 패널](option-panel.html)·팝업·풀페이지).
행확장 편집은 그중 맥락 보존과 좌우 확장에 강한 선택지입니다.

- **콘텍스트 손상 없음**: 팝업·패널이 목록을 덮거나 옆으로 밀어내는 것과 달리, 행확장 편집은 목록을 그대로 둔 채 해당 행만 펼칩니다. 상세를 닫으면 바로 원래 목록 흐름으로 돌아옵니다.
- **좌우로 넓게 표시**: 확장 영역은 행 전체 폭을 쓰므로 좌우로 길게 펼쳐야 하는 상세(여러 열의 정보·서브테이블·편집 폼)를 담기 좋습니다.
- **세로는 제한적, 단순한 상세에 권장**: 좌우와 달리 세로 공간은 넉넉하지 않습니다. 최대 높이를 정하고 넘치면 확장 영역 안에서 스크롤이 생기는 구성도 가능하지만 권장하지 않습니다. 그래서 편집·조회할 정보가 단순할 때 주로 추천합니다. 세로로 길고 복잡한 상세는 팝업·풀페이지가 낫습니다.
- **클릭 흐름을 한 단계 더**: 보통은 `조회 → 목록 클릭 → 팝업/사이드 패널`로 상세 업무를 처리합니다. 행확장 편집을 끼우면 `조회 → 목록 클릭(행 펼침) → 그 상태에서 다시 팝업/사이드 패널`로 단계를 하나 더 둘 수 있습니다. 클릭 흐름이 여러 단계로 이어지는 업무에서 유용합니다.

#### 구성요소

행확장 편집은 [컨텐트 모듈 개요](layout-content.html)의 컨텐트 영역 안에 놓입니다.
일반목록과 뼈대는 같고, 각 행 아래에 확장 상세 행이 아코디언으로 붙는 점이 다릅니다.
정렬·페이지네이션 등 일반 목록 기능은 그대로 씁니다.

1. 펼침 버튼 (행 좌측 ▶)행을 열고 닫는 토글입니다. 좌측 ▶ 아이콘이 열리면 ▼로 바뀌며, 행 어디를 눌러도 토글됩니다.
2. 데이터 행 (부모)평소에는 일반 목록의 한 행입니다. 클릭하면 아래로 상세가 펼쳐지고, 펼쳐진 행은 활성 색으로 구분합니다. (아래 동작 원칙 참고)
3. 확장(상세) 영역펼쳐진 상세입니다. 추가 정보 · 하위 테이블 · 편집 폼을 배치합니다. 좌우 2단(예. 좌: 상세 서브테이블, 우: 편집 폼) 구성도 가능합니다.
4. 확장 영역 내 액션펼친 상세 안에서 상세 보기 · 변경 등을 수행하는 버튼입니다. 하단 우측에 두고, 주 동작은 Primary 1개(예. 저장)로 한정하며 취소를 함께 둡니다.
5. 확장 영역 내 테이블확장 영역 안에 또 다른 테이블 패턴을 얹을 수 있습니다. 상세 항목을 정렬·선택·액션 등 다른 유형으로 표현합니다.

#### 동작 원칙

핵심 원칙상세는 한 번에 한 행만 펼치는 것을 권장합니다(단일 오픈).
여기저기 동시에 펼쳐지면 화면이 산만해지고 어느 상세를 다루는지 흐려집니다.
새 행을 열면 이전에 열린 행은 자동으로 닫힙니다.

- **아코디언 열고 닫기**: 같은 행을 다시 누르면 닫히고, 다른 행을 누르면 그 행이 열리며 이전 행은 닫힙니다.
- **제자리 완결**: 확장 영역에서 편집한 뒤 저장하면 값이 반영되고 상태가 갱신된 뒤 닫히며, 취소하면 폐기 후 닫힙니다. 화면 이동 없이 그 자리에서 마무리됩니다.
- **정렬과 함께 이동**: 헤더 정렬로 행 순서가 바뀌면 펼친 상세도 부모 행을 따라 움직이고, 열린 상태는 유지됩니다.
- **단일 오픈 권장**: 동시 다중 펼침은 특별한 이유가 없으면 피합니다.
- **펼친 행의 색**: [테이블 모듈 공통 정의](grid-basic-behavior.html)의 [행 동작](grid-basic-behavior.html#행-동작)에 있는 활성 행 색 기준을 따릅니다. 편집 폼을 담으면 편집 상태로 주의 색(warning) 연한 톤, 읽기 전용이면 조회 상태로 중립 색(neutral) 연한 톤입니다.

#### 핵심 동작 · 상태

기본 동작(정렬 · 필터 · 상태 처리)은 [테이블 모듈 공통 정의](grid-basic-behavior.html)와 [일반목록](grid-board.html)을 따릅니다.
행확장 편집은 일반 목록 기능(정렬 · 페이지네이션 · 전체보기)을 그대로 쓰면서, 위의 펼침 · 단일 오픈 · 제자리 편집을 더합니다.
Loading · Empty · Error 상태 처리도 테이블 모듈 공통 정의를 따릅니다.

#### 실제 예시

예시 데이터입니다.
‘편집’ 탭은 편집 폼을 담은 확장 영역, ‘조회’ 탭은 읽기 전용 확장 영역입니다.
두 탭에서 행을 눌러 펼친 행의 활성 색을 비교해 봅니다.
다른 행을 누르거나 헤더를 정렬해 열린 상세가 어떻게 움직이는지도 확인합니다.

행확장 편집 · 구조 예시새 탭에서 크게 보기※ 예시 이미지 — 레이아웃/디자인은 확정 아님. 패턴 구조만 참고.
#### Do / Don't

###### Do · 이렇게 합니다

- 목록 맥락을 유지한 채 제자리에서 상세를 확인·편집합니다.
- 한 번에 한 행만 펼칩니다. (단일 오픈)
- 펼친 행에는 확장 영역의 상태(편집 · 조회)에 맞는 활성 색을 유지합니다.
- 좌우로는 넓게 쓰되, 세로로는 단순한 상세만 담습니다.
- 단계가 더 필요하면 펼친 상태에서 팝업·사이드 패널로 한 단계 확장합니다.
- 확장 영역의 액션은 하단 우측에 두고, 각 영역의 주 동작(예. 편집 폼의 저장)은 Primary 1개로 한정합니다.

###### Don't · 이건 피합니다

- 상세가 세로로 길어 확장 영역에 스크롤이 생기게 만들지 않습니다. (→ 팝업 · 풀페이지)
- 여러 행을 동시에 펼쳐 화면을 산만하게 만들지 않습니다.
- 복잡하고 무거운 상세 업무를 확장 영역에 밀어 넣지 않습니다.
- 한 영역에 Primary 버튼을 여러 개 두어 그 영역의 주 동작을 흐리지 않습니다.
