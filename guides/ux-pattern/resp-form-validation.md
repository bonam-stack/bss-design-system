입력값이 규칙에 맞는지 확인하고, 틀린 곳을 사용자가 바로 수정할 수 있게 안내하는 패턴입니다.
 오류는 수정할 자리인 필드에 남기고, 2건 이상일 때만 폼 상단에 요약을 더합니다.

#### 개요 · 언제 쓰나요?

**한 줄 판단**: 형식은 필드를 벗어날 때 · 필수와 종합 검사는 제출할 때입니다.

###### ✓ 이럴 때 사용합니다

- 값을 입력해 처리하는 모든 폼 화면
- 형식 규칙이 있는 항목을 받을 때 → 이메일 · 전화 · 숫자 · 자릿수 · 날짜
- 필수 항목을 채워야 처리할 수 있을 때

###### ✕ 다른 패턴을 사용합니다

- 파일로 여러 건을 한 번에 올릴 때 → [엑셀 대량 등록](grid-excel-upload.html)
- 처리가 실패했을 때 → [확인·경고 다이얼로그](resp-dialog.html)

핵심 원칙오류는 수정할 자리에 남깁니다.
 수정하는 자리가 필드이므로 메시지도 필드에 둡니다.
요약과 알림은 그 위에 두는 보조 수단입니다.

#### 구성요소

1. 요약 배너폼 최상단에 둡니다. 건수를 적고, 항목명을 누르면 그 필드로 이동합니다.
2. 필수 표기값을 받아야 하는 항목은 컨트롤 배경으로 표시하고, 폼 우상단에 범례를 둡니다.
3. 오류 상태컨트롤 테두리를 오류 색(danger)으로 바꾸고 오류 링을 두릅니다. 배경은 칠하지 않습니다 — 여러 필드가 틀리면 색이 화면을 덮어 어디를 고칠지 읽히지 않습니다.
4. 인라인 메시지컨트롤 바로 아래에 원인과 해결을 한 문장으로 적습니다.

| --- | --- | --- |

| 빅 폼 | 프리뷰 레일의 제출 전 확인 | 입력하는 동안 계속 보이므로 배너가 중복됩니다 |

**기준**: 미충족 목록이 항상 보이면 배너를 겹치지 않습니다.

**요약**은 자리와 무관하게 같은 것을 가리키고, **요약 배너**는 기본 폼에서 요약이 놓이는 형태입니다.
 2건 이상일 때 나타났다 사라지는 규칙은 배너에만 해당합니다.
 빅 폼의 프리뷰 레일은 건수와 상관없이 늘 보입니다.

##### 요약은 언제 줄어듭니까

요약 배너는 제출 시점의 목록을 그대로 두지 않고, 남은 오류만 표시합니다.

| 사용자 동작 | 요약 배너 |
| --- | --- |
| 항목을 수정해 정상이 됩니다 | 그 항목만 목록에서 빠지고 건수가 줄어듭니다 |
| 수정한 항목이 다시 규칙에 어긋납니다 | 원래 자리로 다시 들어옵니다 |
| 모든 항목이 정상이 됩니다 | 영역이 사라지고 아래 폼이 올라옵니다 |

기억할 점띄우는 기준과 유지하는 기준은 다릅니다.
 새로 띄우는 것은 2건 이상일 때이고, 유지하는 것은 0건이 될 때까지입니다.
 배너가 사라진 뒤에는 다음 제출까지 다시 띄우지 않습니다.

#### Do / Don't

###### Do · 이렇게 합니다

- 오류를 해당 필드 아래에 인라인으로 표시합니다.
- 메시지에 원인과 해결을 함께 적습니다.
- 형식은 필드를 벗어날 때, 필수와 종합 검사는 제출할 때 판정합니다.
- 오류가 2건 이상일 때 요약 배너를 더하고, 항목에서 필드로 이동할 수 있게 합니다.
- 수정된 항목은 요약에서 즉시 빼고, 모두 정상이 되면 요약 배너를 없앱니다.
- 제출할 때 첫 오류 필드로 스크롤하고 포커스를 옮깁니다.
- 오류가 있으면 처리를 진행하지 않고 결과 영역을 그대로 둡니다.

###### Don't · 이건 피합니다

- 입력하는 중에 오류를 표시하지 않습니다.
- 검증 오류를 사라지는 토스트로만 알리지 않습니다.
- 검증 오류를 전역 안내 메시지에 올리지 않습니다.
- 플레이스홀더로 필수 안내를 대체하지 않습니다.
- 오류가 하나일 때 요약 배너를 새로 띄우지 않습니다. (이미 띄운 배너는 1건이 남아도 닫지 않습니다)
- 색과 테두리만으로 오류를 전달하지 않습니다.
- 조건부로 꺼진 필드를 검증에 포함하지 않습니다.

노드 한 단계에 값을 입력할 때 규칙에 맞는지 확인하고, 틀린 곳을 바로 수정할 수 있게 안내하는 패턴입니다.
 오류는 일반 UI와 같이 필드에 남기고, 좁은 자리라 요약 배너는 두지 않습니다.

노드 본문과 사이드 패널은 폭이 좁습니다.
 그래서 오류를 알리는 수단이 **필드 인라인 하나**이고, 요약 배너는 두지 않습니다.

| 하단 CTA | 필수가 비어 있으면 잠급니다 |

- 사이드 패널에서 값을 입력할 때
- 서버에 확인해야 아는 항목을 받을 때 → 중복확인 · 인증번호

#### 구성요소

1. 필수 표기값을 받아야 하는 항목은 컨트롤 배경으로 표시합니다. 좁은 자리에는 범례를 둘 데가 없어 배경만 씁니다.
2. 자동 입력 표시본인인증·연계 시스템이 채운 값입니다. 라벨 뒤에 배지를 붙이고 읽기 전용으로 둡니다.
3. 오류 상태컨트롤 테두리를 오류 색(danger)으로 바꾸고 오류 링을 두릅니다. 배경은 칠하지 않습니다 — 여러 필드가 틀리면 색이 화면을 덮어 어디를 고칠지 읽히지 않습니다.
4. 인라인 메시지컨트롤 바로 아래에 원인과 해결을 한 문장으로 적습니다.
5. 하단 CTA필수가 비어 있으면 비활성입니다. 캔버스 액션바도 함께 잠깁니다.

참고노드 본문은 검증만 담지 않습니다.
 처리 대상(맥락) · 자동으로 채운 근거 · 입력 · 저장하면 무엇이 생기는지(영향)를 함께 쌓으며, 그 구성은 [입력형 모듈](node-comp-input.html)을 따릅니다.

#### 핵심 동작 · 상태

##### 하단 CTA 는 언제 잠깁니까

필수 항목이 하나라도 비어 있으면 잠그고, 모두 채우면 같은 자리에서 활성으로 바뀝니다.
 값을 다시 지우면 되돌아갑니다.

- 비활성은 주 버튼을 흐리게 두는 것으로 표현합니다. → 회색 버튼으로 바꾸지 않습니다. 무엇을 누르는 자리인지는 남아야 합니다.
- 캔버스 액션바도 함께 잠급니다. → 규정은 [노드형 화면](layout-node.html)이 갖습니다.
- 빈 필수 항목에 인라인 메시지를 달지 않습니다. → 잠겨 있어 제출이 되지 않으므로 지적할 계기가 없습니다. 어느 항목인지는 컨트롤 배경이 가리킵니다.

##### 값이 있는데 틀리면 어떻게 됩니까

잠금은 **비었는지**만 봅니다.
 값이 채워져 있으면 잠기지 않고, 눌렀을 때 그 필드의 인라인 메시지가 받습니다.

- 형식 위반은 잠금으로 막지 않습니다. → 값이 있어도 틀릴 수 있어 잠금 조건으로 쓸 수 없습니다.
- 서버에 확인해야 아는 항목도 잠금으로 막지 않습니다. → 중복 여부는 눌러서 물어봐야 압니다.
- 그래서 인라인 메시지를 없앨 수 없습니다. → 잠금이 걸러 주는 것은 ‘비었다’ 하나입니다.

##### 서버에 확인해야 아는 항목은 어떻게 합니까

컨트롤 옆에 확인 버튼을 두고, 결과를 필드 아래에 적습니다.
 확인했다는 사실 자체가 정보이므로 이 항목에만 정상 표시를 둡니다.

| 상황 | 표시 |
| --- | --- |
| 확인 전 | 아무것도 표시하지 않습니다 |
| 확인해서 쓸 수 있음 | 성공 색 문구를 필드 아래에 둡니다 |
| 확인해서 쓸 수 없음 | 오류 색 문구를 필드 아래에 둡니다 |
| 확인한 뒤 값을 고침 | 표시를 걷습니다 |

- 값이 바뀌면 이전 확인 결과를 걷습니다. → 확인한 값과 지금 값이 다르면 그 표시는 거짓입니다.
- 확인을 마쳐야 저장할 수 있으면 그 조건을 안내 문구로 적습니다. → 잠금만으로는 왜 안 되는지 알 수 없습니다.

##### 사이드 패널이면 무엇이 다릅니까

검증 규정은 자리와 무관하게 같습니다.
 필수 표기 · 오류 상태 · 인라인 메시지 · 잠금 넷이 그대로 걸립니다.

| 무엇 | 노드 본문 | 사이드 패널 |
| --- | --- | --- |
| 검증 규정 | 같습니다 | 같습니다 |
| 하단 버튼 | 전체 폭 주 버튼 하나 | 우측 정렬 · 취소가 함께 놓입니다 |

- 패널이 열려 있는 동안 그 노드는 편집중입니다. → 상태 정의는 [노드형 화면](layout-node.html)을 따릅니다.
- 노드 본문과 패널에 서로 다른 검증 방식을 두지 않습니다.

##### 항목 이름과 안내 문구는 어떻게 씁니까

| 구분 | 이렇게 씁니다 | 이건 피합니다 |
| --- | --- | --- |
| 필수 셀렉트 | 처리 구분 선택 | 선택 |
| 선택 항목 | 의견 입력 | 의견 입력 (선택) |

- 필수 항목을 텍스트 입력처럼 그리지 않습니다. → 고르는 자리는 셀렉트로 두어 꺾쇠가 보이게 합니다.
- ‘선택’을 두 뜻으로 쓰지 않습니다. → 고르라는 뜻과 선택 항목이라는 뜻이 한 화면에 겹치면 필수인지 아닌지 읽을 수 없습니다.
- 선택 항목에 따로 표기를 두지 않습니다. → 필수는 컨트롤 배경으로 이미 갈립니다.

##### 일반 UI 탭과 같은 것

아래는 노드 UI에서도 같으므로 일반 UI 탭이 규정합니다.

| 무엇 | 어디에 |
| --- | --- |
| 오류 상태 · 인라인 메시지 규격 | 일반 UI 탭 · 구성요소 |
| 필드 상태 5종과 정상 표시를 지양하는 이유 | 일반 UI 탭 · 필드 상태 |
| 판정 시점(입력 중 · 필드 이탈 · 제출) | 일반 UI 탭 · 언제 판정합니까 |
| 메시지 문체 | 일반 UI 탭 · 메시지는 어떻게 씁니까 |
| 검증 오류를 올리지 않는 자리 | 일반 UI 탭 · 어디에 표시합니까 |

#### 실제 예시

이 탭에는 **눌러 보는 예시 화면을 두지 않습니다.**
 위 **핵심 동작 · 상태**에 넣은 국면 화면이 예시를 겸합니다.
 확인할 곳은 잠금 · 형식 오류 · 서버 확인 · 사이드 패널 네 가지입니다.

#### Do / Don't

###### Do · 이렇게 합니다

- 필수 항목이 비어 있으면 하단 CTA를 잠그고, 모두 채우면 활성으로 바꿉니다.
- 비활성은 주 버튼을 흐리게 두어 무엇을 누르는 자리인지 남깁니다.
- 값이 있는데 틀리면 잠그지 않고 필드 인라인으로 알립니다.
- 자동으로 채운 값에는 배지를 붙이고 읽기 전용으로 둡니다.
- 서버에 확인해야 아는 항목에만 정상 표시를 두고, 값이 바뀌면 걷습니다.
- 고르는 항목은 셀렉트로 두고 기본 문구에 항목 이름을 넣습니다.

###### Don't · 이건 피합니다

- 좁은 자리에 요약 배너를 두지 않습니다.
- 빈 필수 항목에 인라인 메시지를 달지 않습니다.
- 비활성 주 버튼을 회색 버튼으로 바꾸지 않습니다.
- 형식 위반과 서버 확인을 잠금 조건으로 쓰지 않습니다.
- 노드 본문과 사이드 패널에 서로 다른 검증 방식을 두지 않습니다.
- ‘선택’을 고르라는 뜻과 선택 항목이라는 뜻으로 겹쳐 쓰지 않습니다.
