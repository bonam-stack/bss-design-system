시스템이 작업을 처리하는 과정을 사용자에게 인지시키는 노드 모듈입니다.
처리 상태와 CTA를 중심으로, 특이사항·기본 정보·AI 가이드를 필요에 따라 더합니다.

#### 개요 · 언제 쓰나요?

처리형은 노드 모듈 유형의 하나입니다.
점검·발송·일괄 처리처럼 시스템이 작업을 처리하는 과정을 사용자에게 인지시키는 노드 모듈을 어떤 구조로 설계하는지 규정합니다.
값을 읽거나 고르는 것이 아니라, 처리 상태(대기 → 진행 → 완료)가 바뀌는 것을 보여 주는 것이 핵심입니다.

###### ✓ 이럴 때 사용합니다

- 여러 항목을 순차로 점검할 때
- 안내 SMS처럼 대상에게 순차로 발송할 때
- 대량 항목을 엑셀로 올려 한꺼번에 처리할 때

###### ✕ 다른 노드 모듈 유형을 사용합니다

- 값을 읽고 확인만 하면 → 조회형
- 값을 고르게 하면 → 선택형
- 값을 넣거나 고치게 하면 → 입력형
- 고객·상담사가 주고받아야 진행되면 → 상호작용형

##### 기본 틀

처리형 노드 모듈은 위에서 아래로 특이사항(선택) · 기본 정보(선택) · 처리 상태 · AI 가이드(선택) · CTA를 쌓습니다.
처리 상태가 이 모듈의 주 거동이며, 나머지 자리는 처리 방식에 따라 더합니다.
진입 즉시 자동으로 점검하는 형태는 처리 상태 하나만 두는 가장 단순한 골격이 됩니다.
공통 자리(특이사항·기본 정보·AI 가이드)는 조회형과 같은 역할·이름으로 두고, 처리 상태만 이 패턴의 고유 표현입니다.

1. 특이사항 (선택 · 최상단)업무 대상의 특이사항을 콜아웃으로 알립니다. 기본은 두지 않고, 꼭 필요할 때만 표시하는 옵션 요소입니다.
2. 기본 정보 (선택)무엇을 처리하는지 처리 대상·맥락을 보여 줍니다. 정보 요약을 기본으로 쓰며, 상담사가 확인 후 실행하는 형태에 둡니다. 자동으로 점검하는 형태에서는 생략하는 옵션 요소입니다.
3. 처리 상태이 모듈이 보여 줄 핵심입니다. 처리 체크리스트나 처리 상태 카드로 처리 과정을 진행 상태와 함께 보여 줍니다.
4. AI 가이드 (선택)처리 결과·영향에 대한 참고 안내입니다. 필수가 아닌 옵션 요소이며, 주의가 필요할 때만 둡니다.
5. CTA상담사가 처리를 실행하는 버튼입니다. 모든 노드 모듈에 공통이며 맨 아래로 분리합니다. 자동으로 점검하는 형태는 버튼 없이 완료 시 다음으로 넘어갑니다.

한 패턴이 늘 기본 틀 하나로만 나오지는 않습니다.
기본 틀과, 그 구조를 지킬 수 없는 자동 점검 골격을 나란히 둡니다.

##### 기본

특이사항 → 기본 정보 → 처리 상태 → AI 가이드 → CTA 순으로 쌓은 기본 골격입니다.

##### 자동 점검 골격 (제약형)

자동 점검은 진입 즉시 체크리스트만 돌아가 기본 틀을 지킬 수 없습니다.
처리 체크리스트 하나만 들어가고, 처리 상태나 다른 자리는 넣지 않습니다.

#### 구성요소

처리 상태 자리에 넣는 표현입니다.
처리 체크리스트가 기본이고, 한 건짜리 처리 상태 카드로 넓혀 씁니다.

##### 처리 체크리스트

여러 항목·대상을 순차로 점검·처리하고, 각 항목의 상태를 좌측 아이콘(대기 → 진행 → 완료)으로 보여 줍니다.
진입 즉시 자동 점검하는 형태, 상담사가 실행 버튼을 눌러 대상별로 처리하는 형태, 이름·역할이 있는 검증 리스트까지 같은 표현으로 씁니다.

**규칙** 상태 아이콘은 좌측에 둡니다.
자동 점검형은 실행 버튼 없이 진입 즉시 점검하고, 전원 통과하면 버튼 없이 넘어갑니다.
실패 항목은 배경색이 아니라 실패 아이콘으로만 표시합니다.
한 번 실행하면 상태가 순차로 채워지므로 접히는 아코디언에 담지 않습니다.

##### 처리 상태

한 건의 점검·처리가 대기·진행·완료·실패 중 어디에 있는지 한 줄 카드로 보여 줍니다.

**규칙** 상태는 아이콘으로만 구분하고(대기·진행·완료·실패), 좌측 색 라인이나 채운 배경을 넣지 않습니다.
실패 상태에는 카드 우측에 조치 버튼을 둡니다.
단순 재시도가 아니라, 실패를 해소하려면 무엇을 해야 하는지를 버튼 라벨로 보여 주고 그 조치를 처리할 자리로 이동시켜 처리하고 돌아오게 하는 버튼입니다.

#### 핵심 동작 · 상태

##### 자리와 표현

- 처리 상태가 주 거동입니다. 위쪽에는 기본 정보(처리 대상 맥락)를, 가운데에는 처리 상태를 둡니다.
- 자동으로 점검하는 형태는 기본 정보·AI 가이드·CTA를 모두 생략하고 처리 상태 하나만 둡니다. 상담사 개입이 없는 것이 곧 골격입니다.
- 상담사가 확인 후 실행하는 형태(발송·일괄 처리)는 기본 정보(처리 대상)를 먼저 두고, 필요하면 AI 가이드를 더합니다.
- 구분선은 기본 정보와 필수 정보 사이에만 넣습니다. 필수 정보끼리는 제목으로 나뉘어도 넣지 않고, AI 가이드 앞뒤에도 넣지 않습니다. CTA만 맨 아래로 분리합니다.
- 기본 정보의 영역 제목은 선택입니다. 제목 없이 내용만 두어도 되고, 내용만으로 무엇인지 읽히면 제목을 넣지 않습니다.
- AI 가이드는 절제합니다. 유도할 결정이 없으므로 대개 생략하고, 처리 결과·영향에 대한 주의가 필요할 때만 처리 상태 아래에 둡니다.

표현별 규칙은 위 구성요소의 각 표현 설명에 함께 적었습니다.
##### 처리 상태 표시

- 처리 상태는 좌측 아이콘으로 대기(빈 원) → 진행(스피너) → 완료(체크) 순으로 바뀝니다.
- 실패 항목은 배경색으로 강조하지 않고 실패 아이콘으로만 표시합니다.
- 자동으로 점검하는 형태는 정상 완료 시 CTA 없이 다음으로 넘어갑니다.

##### 진행 표시

- 노드 모듈이 여러 단계(페이지)로 진행되면, 단계 표시는 모듈 안이 아니라 액션바에 둡니다. (예. 액션바 타이틀 ‘일괄 처리 (1/2)’)

#### 실제 예시

처리형 표현을 조합해 만든 노드 모듈 예시입니다.
모듈 위 번호 핀이 어느 부분이 어떤 표현인지 가리킵니다.

#### Do / Don't

###### Do · 이렇게 합니다

- 노드 안에서의 클릭은 1~2회로 권장합니다. 한 노드에 과도한 단계·클릭을 만들지 않습니다.
- 자동으로 점검하는 형태는 처리 상태 하나로 단순하게 만듭니다.
- 상담사가 실행하는 형태는 기본 정보(처리 대상)를 먼저 보여 주고 CTA로 처리합니다.
- 처리 상태는 좌측 아이콘으로 대기 → 진행 → 완료를 보여 줍니다.

###### Don't · 이건 피합니다

- 처리형 노드 모듈에 값을 고르거나 넣는 표현을 넣지 않습니다. (→ 선택형·입력형)
- 자동으로 점검하는 형태에 CTA를 두지 않습니다. 정상 완료 시 버튼 없이 다음으로 넘어갑니다.
- 유도할 결정이 없는데 AI 가이드를 습관적으로 넣지 않습니다.
- 실패 항목을 배경색으로 강조하지 않습니다. 실패 아이콘으로만 표시합니다.
