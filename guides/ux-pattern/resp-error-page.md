화면을 쓸 수 없을 때 무엇이 일어났고 다음에 무엇을 할지 안내하는 화면입니다.
화면은 쓸 수 있고 알릴 것만 있을 때는 화면 상단 고정 메시지(스트라이프)가 받습니다.

#### 개요 · 언제 쓰나요?

**한 줄 판단**: 화면을 쓸 수 없으면 전역 예외 화면 · 쓸 수 있는데 알릴 것이 있으면 스트라이프입니다.

이 페이지는 둘을 함께 규정합니다.

| 구분 | 언제 | 예 |
| --- | --- | --- |
| 전역 예외 화면 | 화면을 쓸 수 없습니다 | 세션 만료 · 권한 없음 · 초기 로드 실패 |
| 스트라이프 | 화면은 쓸 수 있고 알릴 것이 있습니다 | 전역 공지 · 시스템 상태 |

###### ✓ 이럴 때 사용합니다

- 화면 전체를 진행할 수 없을 때 → 세션 만료 · 권한 없음
- 화면을 처음 여는 데 실패했을 때 → 서버 오류 · 네트워크 끊김

###### ✕ 다른 패턴을 사용합니다

- 입력값이 규칙에 맞지 않을 때 → [폼 유효성 체크](resp-form-validation.html)
- 결정을 물어야 할 때 → [확인·경고 다이얼로그](resp-dialog.html)
- 눌러서 생긴 처리가 실패했을 때 → [확인·경고 다이얼로그](resp-dialog.html)의 정보 Alert
- 알고 넘어가도 되는 결과일 때 → [토스트·스낵바](resp-toast.html)

핵심 원칙막는 화면에는 반드시 나가는 길을 둡니다.

무엇이 일어났는지만 알리고 다음 행동을 주지 않으면 사용자가 할 수 있는 일은 뒤로가기뿐입니다.

#### 구성요소

1. 이미지상황을 한눈에 알리는 그림입니다. 선택이며, 없어도 제목·설명만으로 성립합니다.
2. 제목필수입니다. 무엇이 일어났는지 한 줄로 적습니다.
3. 설명필수입니다. 왜 그런지와 무엇을 하면 되는지를 적습니다.
4. 복구 CTA다음 행동 버튼입니다. 재로그인 · 다시 시도 · 이전으로 · 문의처럼 상황에 맞는 동작을 담습니다.

유의사항이미지는 예외 유형에 따라 다르게 노출합니다.

모든 상황을 갖추지는 않고 자주 나오는 몇 가지를 정해 두고 씁니다.

정해 둔 것이 없으면 이미지 없이 제목·설명·CTA로 구성합니다.

#### 핵심 동작 · 상태

##### 예외 4종과 복구 동선

| 예외 | 복구 CTA |
| --- | --- |
| 세션 만료 | 다시 로그인 |
| 권한 없음 | 이전으로 · 접근 요청 |
| 서버 오류 | 다시 시도 |
| 네트워크 끊김 | 다시 시도 |

- 유형마다 다음 행동이 다릅니다. → 같은 CTA 문구를 돌려 쓰지 않습니다.
- 권한 없음에만 CTA를 둘 둡니다. → 되돌아가는 길과 요청하는 길이 함께 필요한 유일한 유형입니다.

##### 어디까지 덮습니까

| 덮는 범위 | 유형 | 남기는 것 |
| --- | --- | --- |
| 전체 뷰포트 | 세션 만료 | 없습니다 |
| 본문 | 권한 없음 · 서버 오류 · 네트워크 끊김 | 사이드 내비게이션 바 · GNB · 커뮤니케이터 · 브레드크럼 |

**기준**: 남은 선택지가 있느냐입니다.

로그아웃 상태에서는 어느 메뉴로도 갈 수 없으므로 전체를 덮습니다.

다른 메뉴로 갈 수 있어야 하면 [공통 레이아웃](layout-common.html)의 네 영역을 남기고 본문만 덮습니다.

##### 에러코드는 어떻게 적습니까

**규정**: 에러코드를 화면에 노출합니다.

문의하거나 장애를 접수할 때 사용자와 담당자가 같은 건을 가리킬 식별자가 필요합니다.

- 화면 맨 아래에 보조로 작게 적습니다. → 본문보다 작고 흐리게 두어 해결 안내를 가리지 않게 합니다.
- 해결 안내가 먼저입니다. → 사용자가 할 수 있는 일은 재시도와 문의이지 코드 해석이 아닙니다.
- HTTP 응답이 없어도 식별자를 둡니다. → 네트워크 끊김처럼 숫자 코드가 없으면 상태를 나타내는 문구로 대신합니다.

유의사항가이드가 규정하는 것은 **노출 여부와 자리·크기**입니다.

어떤 값을 쓸지는 시스템이 내려주는 코드를 따르며, 화면의 `CODE 401` 은 표기 위치를 보이기 위한 예시입니다.

##### 메시지는 어떻게 씁니까

| 구분 | 이렇게 씁니다 | 이건 피합니다 |
| --- | --- | --- |
| 제목 | 세션이 만료되었습니다 | 401 Unauthorized |
| 설명 | 보안을 위해 로그아웃되었습니다 | 인증 토큰이 유효하지 않습니다 |
| CTA | 다시 로그인 | 확인 |

- 기술 용어가 아니라 사용자가 겪은 일로 씁니다.
- CTA에는 무엇을 하는 버튼인지 적습니다. → ‘확인’처럼 아무 동작이나 가리키는 말을 쓰지 않습니다.

##### 스트라이프는 무엇을 받습니까

여기부터는 예외 화면이 아니라 **스트라이프**입니다.

화면이 살아 있을 때 쓰는 다른 컴포넌트이지만, 어느 쪽을 쓸지 함께 판단해야 하므로 이 페이지가 같이 규정합니다.

표준설계가이드는 스트라이프를 Global Message라 부르고 **화면 상단 고정 메시지**로 정의합니다.

전체 사용자에게 공통적인 상태나 공지 사항을 전달해야 하는 경우에 씁니다.

- 시스템 상태 또는 전역 안내가 필요한 경우에 사용합니다.
- 사용자에게 필수적으로 전달해야 하는 정보가 있는 경우에 사용합니다.
- 현재 화면과 관계없이 전역적으로 동일하게 안내해야 하는 경우에 사용합니다.

**기준**: 사용자가 시키지 않은 것만 받습니다.

사용자가 버튼을 눌러 생긴 처리 실패는 [확인·경고 다이얼로그](resp-dialog.html)의 정보 Alert이 받습니다.

| 갈래 | 언제 | 예 |
| --- | --- | --- |
| 전역 공지 | 화면과 무관하게 모든 사용자에게 같은 내용을 알립니다 | 시스템 점검 예고 · 장애 공지 |
| 시스템 상태 | 사용자가 시작하지 않은 일이 화면 전반에 걸립니다 | 자동 저장 실패 · 세션 만료 임박 · 연결 끊김 · 읽기 전용 전환 |

- 두 갈래를 색으로 구분합니다. → 같은 자리를 나눠 쓰므로 색이 유일한 구분 단서입니다. → 전역 공지는 주의 색(warning), 시스템 상태는 오류 색(danger)을 씁니다. 상태 팔레트에 있는 색을 그대로 쓰고 새로 만들지 않습니다.
- 눌러서 생긴 실패는 이 자리에 올리지 않습니다. → 스트라이프는 누른 자리와 떨어진 화면 상단에 뜨므로 어느 동작의 실패인지 가리킬 수 없습니다. → 원인 · 다음 행동 · 실패 건수를 한 줄에 담을 수 없습니다.
- 검증 오류는 이 자리에 올리지 않습니다. → 고칠 자리가 필드이므로 메시지도 필드에 둡니다.

같은 저장 실패라도 무엇이 그 일을 시켰느냐로 갈립니다.

| 무엇이 시켰습니까 | 무엇이 받습니까 |
| --- | --- |
| 사용자가 ‘저장’을 눌렀습니다 | 정보 Alert |
| 시스템이 자동 저장을 돌렸습니다 | 스트라이프 |

##### 스트라이프는 어디에 뜹니까

GNB 바로 아래 줄의 가운데에, 폭을 줄여 겹쳐 뜹니다.
 모양과 사라지는 방식은 [토스트·스낵바](resp-toast.html)의 스트라이프 절을 따릅니다.

그 줄은 일반 UI에서는 브레드크럼이, 노드 UI에서는 상담 대상 고객 요약이 쓰고 있습니다.

- 일반 UI와 노드 UI 모두 그 줄의 가운데를 덮습니다. → 양옆의 브레드크럼과 고객 요약은 그대로 보입니다.
- 스트라이프가 사라지면 원래 상태로 돌아옵니다.

#### 실제 예시

이 패턴에는 **눌러 보는 예시 화면을 두지 않습니다.**

위 **핵심 동작 · 상태**에 넣은 국면 화면이 예시를 겸합니다.

확인할 곳은 유형별 CTA · 덮는 범위 · 에러코드 표기 · 스트라이프 동작 네 가지입니다.

##### 예시 화면을 두지 않는 이유

- **상태 전이가 하나입니다.** 화면이 덮이고, CTA를 누르면 벗어납니다. 순서대로 눌러 봐야 알 수 있는 단계가 없습니다.
- **규정이 전부 비교입니다.** 유형별 CTA · 덮는 범위 · 코드 표기 · 얹기와 덮기는 두 컷 이상을 나란히 놓아야 읽힙니다. 한 번에 한 상태만 보이는 화면으로는 이 비교를 할 수 없습니다.
- **제품에 없는 조작을 만들어야 합니다.** 예외는 사용자가 부르는 것이 아니라 겪는 것입니다. 예외를 띄우는 버튼이나 화면 유형을 바꾸는 토글은 제품에 없는 장치이고, 그 장치가 규격으로 오해됩니다.

기억할 점예시 화면이 없는 것은 빠뜨린 것이 아니라 이 패턴의 성격 때문입니다.

다만 전이를 규정하게 되면 달라집니다.

덮이는 순간의 움직임 · 포커스가 가는 곳 · CTA를 누른 뒤의 복귀 동선을 정하기로 하면 그때 예시 화면을 만듭니다.

#### Do / Don't

###### Do · 이렇게 합니다

- 상황마다 복구 CTA를 하나 이상 둡니다.
- 제목과 설명을 사용자가 겪은 일로 씁니다.
- 세션 만료만 전체 뷰포트를 덮고, 나머지 셋은 본문만 덮습니다.
- 에러코드를 화면 맨 아래에 보조로 작게 노출합니다.
- 스트라이프의 전역 공지와 시스템 상태를 상태 팔레트의 서로 다른 색으로 구분합니다.
- 눌러서 생긴 처리 실패는 정보 Alert에 맡깁니다.

###### Don't · 이건 피합니다

- 복구 CTA 없이 ‘오류가 발생했습니다’만 띄우지 않습니다.
- 기술 에러코드만 화면에 크게 내세우지 않습니다.
- 입력값 검증에 이 화면을 쓰지 않습니다.
- 처리만 실패했을 때 화면 전체를 덮지 않습니다.
- 유형이 달라도 같은 CTA 문구를 돌려 쓰지 않습니다.
- 전역 공지를 특정 화면에서만 띄우지 않습니다.
