고객 · 계약처럼 여러 단계를 거쳐 정해지는 조회조건을 지정하는 표준 기능 패턴입니다.
업무세션에 값이 정해져 있으면 그 값으로 화면을 바로 열고, 정해지지 않은 단계만 사이드 패널에서 고르게 합니다.

#### 개요 · 언제 쓰나요?

업무 화면에는 무엇을 대상으로 업무를 하는지 정하는 조회조건이 있습니다. (예. 고객 · 계약) 이 값은 고객을 찾아 고르고, 그 고객의 계약을 고르는 것처럼 여러 단계를 거쳐야 정해집니다.
상담 중에는 업무세션이 이 값을 이미 담고 있는 경우가 많으므로, 업무 화면은 대부분 그 값으로 바로 열립니다.
업무세션에 값이 없거나 앞 단계까지만 있을 때만 사이드 패널에서 남은 단계를 고릅니다.

이 문서는 [엑셀 업로드하기](grid-excel-upload.html)처럼 정해진 화면을 제공하지 않습니다.
단계 수 · 단계마다 보여 줄 정보 · 고를 수 있는 개수는 업무마다 정하고, 이 문서는 그 위에서 지킬 흐름을 정의합니다.

###### ✓ 이럴 때 사용합니다

- 조회조건을 정하는 데 여러 단계를 거쳐 범위를 좁혀야 할 때
- 앞 단계에서 고른 값에 따라 다음 단계에서 고를 수 있는 항목이 달라질 때

###### ✕ 다른 패턴을 사용합니다

- 한 번의 입력으로 정해지는 조회조건 → [조회조건 모듈](search-conditions.html)의 일반 필드

핵심 원칙1. 업무세션에 정해진 값이 있으면 그 값으로 시작합니다. 필요한 단계까지 모두 정해져 있으면 묻지 않고 바로 컨텐트를 불러옵니다.
2. 단계가 몇 개든 조회조건에는 필드 하나만 두고, 단계는 사이드 패널에서 진행합니다. 마지막 단계를 비교하며 골라야 하는 업무는 마지막 단계만 본문에서 고를 수 있습니다.
3. 업무세션에서 이어받은 고객은 바꾸지 않습니다.
4. 업무 화면은 조회조건을 지정한 상태로만 씁니다.

#### 들어오는 세 가지 경우

같은 업무 화면도 업무세션에 무엇이 정해져 있느냐에 따라 다르게 시작합니다.

| 업무세션의 상태 | 장면 (예. 계약까지 정하는 업무) | 업무 화면에 들어오면 | 사용자가 고르는 단계 |
| --- | --- | --- | --- |
| 업무에 필요한 단계까지 모두 정해져 있음 | 고객 A의 업무세션에서 계약을 정한 뒤 업무를 엽니다 | 조회조건 필드에 그 값을 채우고 컨텐트를 바로 불러옵니다 · 사이드 패널은 열지 않습니다 | 없음 |
| 앞 단계까지만 정해져 있음 | 고객 A의 업무세션에서 계약을 정하지 않고 업무를 엽니다 | 정해진 단계를 채운 채로 사이드 패널을 열고, 다음 단계부터 이어 갑니다 | 계약 선택 |
| 정해진 값이 없음 | 업무세션 없이 사이드 내비게이션 바 메뉴에서 업무를 엽니다 | 사이드 패널을 바로 열어 첫 단계부터 정하게 합니다 | 조건 입력 → 고객 선택 → 계약 선택 |

- **이어받은 값으로 조회조건이 다 채워지지 않으면 화면을 열 때 사이드 패널을 함께 엽니다**: 조회조건을 채우지 않으면 본문을 불러올 수 없으므로, 사용자가 조회조건 필드를 찾아 누르지 않고 바로 남은 단계를 입력하게 합니다. 업무세션에 정해진 값이 없을 때도 같은 이유로 패널을 엽니다.
- **사이드 패널을 쓰지 않는 조회조건도 남은 입력으로 바로 이어지게 합니다**: 단계 없이 한 번의 입력으로 정해지는 조회조건이면 페이지 로딩 직후 비어 있는 첫 입력란에 포커스를 둡니다. 사용자가 조회조건 필드를 찾아 누르지 않고 바로 입력하게 하기 위함입니다. ([조회조건 모듈](search-conditions.html#session))
- **업무세션에서 이어받은 고객은 바꿀 수 없습니다**: 업무세션의 고객이 곧 그 업무 화면의 고객입니다. 다른 고객의 업무는 그 고객의 업무세션에서 진행합니다. ([GNB](layout-gnb.html#main-session))
- **그 밖의 단계는 조회조건 필드에서 사이드 패널을 열어 바꿉니다**: 패널은 지금 정해진 값이 채워진 채로 열리고, 사용자는 바꿀 단계만 고칩니다.
- **바꾼 값은 그 화면에만 적용합니다**: 이미 열려 있는 다른 업무 화면은 그대로입니다.
- **값을 바꾼 화면에서 다른 업무로 넘어가면 바뀐 값이 이어집니다**: [Cross-linking](work-connect.html#cross-linking)으로 다른 업무를 열면 지금 화면의 업무세션 값이 그대로 넘어갑니다.

화면을 열면 조회조건 필드에 고객과 계약이 채워지고, 스켈레톤 다음에 컨텐트가 나옵니다.
고객 값 앞의 잠금 아이콘을 확인합니다.

계약까지 정해져 있을 때 · 패널 없이 바로 열립니다새 탭에서 크게 보기※ 예시 이미지 — 레이아웃/디자인은 확정 아님. 패턴 구조만 참고.
#### 기획할 때 정할 것

이 UX 패턴을 적용할 때 화면설계서에 아래 항목을 정해 적습니다.

1. 같은 업무 대상을 쓰는 다른 업무와 단계 구성을 맞추었는지 → [조회조건 모듈 · 업무 간 일관성](search-conditions.html#consistency)
2. 업무세션에서 어느 단계까지 이어받는지 → [들어오는 세 가지 경우](#session)
3. 몇 단계를 거치는지, 단계마다 무엇을 고르는지 → [단계 설계](#steps)
4. 단계마다 목록에 보여 줄 정보 → [단계 설계](#steps)
5. 단계마다 하나만 고르는지, 여러 개를 고를 수 있는지 → [단계 설계](#steps)
6. 마지막 단계를 사이드 패널에서 고르는지, 본문에서 비교하며 고르는지 → [마지막 단계를 본문에서 고르는 경우](#last-step-in-body)
7. 이 업무에서 쓸 수 없는 항목을 가르는 기준 → [예외 처리](#exceptions)

#### 적용 조건

- **조회조건 모듈에 필드 하나로 둡니다**: 단계를 모두 마치고 확정한 값을 그 필드에 표시합니다.
- **단계는 사이드 패널 안에서 끝냅니다**: 조건 입력부터 마지막 단계의 선택까지 패널 안에서 진행합니다. 조회조건 모듈과 본문에는 단계를 펼치지 않습니다. ([예외](#last-step-in-body))
- **업무가 단계 구성을 정합니다**: 몇 단계를 거칠지, 단계마다 무엇을 고를지는 업무에 따라 다릅니다. ([단계 설계](#steps))

#### 사이드 패널로 단계를 모으는 이유

단계를 어디에 펼치느냐에 따라 화면 구성이 달라집니다.

| 단계를 펼치는 곳 | 화면에 생기는 일 |
| --- | --- |
| 조회조건 모듈 | 단계마다 필드가 늘어 모듈이 여러 줄이 되고, 앞 단계를 고르기 전에는 쓸 수 없는 필드가 함께 놓입니다 |
| 본문 | 단계를 진행하는 동안 업무를 볼 자리가 없어지고, 지정을 마치면 화면이 통째로 바뀝니다 |
| 사이드 패널 | 단계가 몇 개든 조회조건 모듈에는 필드 하나만 남고, 패널을 닫으면 본문이 그대로 업무 화면이 됩니다 |

- **단계가 늘어도 화면 구성은 그대로입니다**: 단계는 패널 안의 아코디언 한 칸씩 늘어날 뿐, 조회조건 모듈과 본문의 배치는 바뀌지 않습니다.
- **한 번에 한 단계에만 집중합니다**: 앞 단계를 마치면 다음 단계가 열리므로, 아직 고를 수 없는 항목이 화면에 함께 놓이지 않습니다.

#### 단계 설계

이 UX 패턴은 단계를 오가는 방식만 정합니다.
단계의 내용은 업무가 정합니다.

| 항목 | UX 패턴이 정하는 것 | 업무가 정하는 것 |
| --- | --- | --- |
| 단계 수 | 한 번에 한 단계만 열고, 앞 단계를 마치면 다음 단계를 엽니다 | 몇 단계를 거칠지 · 2단계 · 3단계에 그치지 않고 범위를 더 좁혀야 하면 단계를 늘립니다 |
| 단계마다 고르는 것 | 첫 단계는 조건을 입력해 찾고, 그다음 단계부터는 앞 단계의 결과 안에서 고릅니다 | 단계마다 무엇을 고를지 · 첫 단계가 고객일 필요는 없습니다 |
| 목록에 보여 줄 정보 | 고를 항목을 가를 수 있는 정보를 함께 보여 줍니다 | 목록마다 붙일 정보의 종류와 순서 (예. 고객 유형 · 가입일, 계약 상태 · 상품) |
| 고르는 개수 | 여러 개를 고른 단계는 고른 값 모두를 다음 단계와 결과로 넘깁니다 | 단계마다 하나만 고를지, 여러 개를 고를 수 있게 할지 |

- **앞 단계를 바꾸면 그 뒤 단계의 선택을 비웁니다**: 앞 단계의 결과가 바뀌면 뒤 단계에서 고른 값이 더는 맞지 않기 때문입니다.
- **‘초기화’는 패널 안에서 고르던 값만 비웁니다**: 이미 확정해 업무 화면에 적용된 값은 지우지 않습니다.

아래는 단계 구성의 예입니다.

| 구성 예 | 단계 |
| --- | --- |
| 고객까지 정하는 업무 | 조건 입력 → 고객 선택 |
| 계약까지 정하는 업무 | 조건 입력 → 고객 선택 → 계약 선택 |
| 여러 계약을 함께 다루는 업무 | 조건 입력 → 고객 선택 → 계약 선택 (여러 개) |

#### 마지막 단계를 본문에서 고르는 경우

업무에 따라서는 마지막 단계의 항목을 바꿔 가며 내용을 점검한 뒤에 확정하고 진행해야 합니다. (예. 고객의 여러 계약을 차례로 열어 보며 처리할 계약을 정하는 업무) 이런 업무에서 마지막 단계를 사이드 패널에 두면, 항목을 바꿀 때마다 패널을 다시 열어야 합니다.
그래서 마지막 단계만 본문에서 고르는 구성을 허용합니다.

- **마지막 단계만 본문으로 옮깁니다**: 앞 단계는 그대로 조회조건 모듈의 필드와 사이드 패널에서 정합니다.
- **본문은 다단 구성으로 나눕니다**: 한 단에 마지막 단계의 목록을 두고, 다른 단에 고른 항목의 내용을 보여 줍니다. ([다단 구성](layout-columns.html))
- **목록에서 항목을 바꾸면 내용 단만 바뀝니다**: 앞 단계에서 정한 값과 조회조건 모듈의 필드는 그대로 둡니다.
- **업무세션에 마지막 단계의 값이 정해져 있으면 그 항목을 고른 상태로 엽니다**: 사용자는 필요할 때만 목록에서 다른 항목으로 바꿉니다.

#### 결과와 복귀

| 결과 | 컨텐트 모듈로 넘기는 값 | 복귀 지점 |
| --- | --- | --- |
| 성공 | 확정한 단계까지의 값 · 여러 개를 고른 단계는 고른 값 모두 | 조회조건 필드에 확정한 값을 표시하고 컨텐트를 다시 불러옵니다 |
| 실패 | 없음 | 사이드 패널 안에 머무릅니다 · 조건을 고쳐 다시 찾습니다 |
| 중단 | 없음 | 패널을 열기 전의 화면으로 돌아가고, 기존 값은 그대로 둡니다 |
| 값 없이 들어와 중단 (가안) | 없음 | 컨텐트는 조회 전 상태로 두고 불러오지 않습니다 · 조회조건 필드에서 패널을 다시 열 수 있게 합니다 |

- **확정하면 패널을 닫고 컨텐트를 다시 불러옵니다**: 불러오는 동안은 Loading 상태(스켈레톤)로 보여 줍니다.
- **값을 바꾸면 앞 값의 결과를 남기지 않습니다**: 새 값으로 다시 불러오며, 앞 값의 결과가 섞여 보이지 않게 합니다.
- **조회 전 상태는 업무를 진행할 수 없는 상태입니다**: 조회조건을 지정하지 않은 채로는 컨텐트를 불러오지 않으므로, 지정하지 않은 화면에서 업무를 진행하지 않습니다. ([테이블 모듈 공통 정의](grid-basic-behavior.html))

#### 예외 처리

| 상황 | 처리 |
| --- | --- |
| 조건에 맞는 항목이 없습니다 | 그 단계의 목록 자리에 Empty 안내를 두고, 조건을 고쳐 다시 찾게 합니다 |
| 앞 단계에서 고른 값 아래에 고를 항목이 없습니다 | 그 단계의 목록 자리에 Empty 안내를 두고, 앞 단계에서 다시 고를 수 있게 합니다 |
| 업무세션에서 이어받은 값을 이 업무에서 쓸 수 없습니다 | 쓸 수 있는 단계까지는 그대로 두고, 그다음 단계를 열어 다시 고르게 합니다 |
| 목록에 이 업무에서 쓸 수 없는 항목이 있습니다 | 목록에는 보여 주되 고를 수 없게 표시합니다 |
| 찾는 중에 오류가 났습니다 | 그 단계 안에서 오류를 알리고 다시 시도할 수 있게 합니다 |
| 권한이 없는 항목입니다 | [권한 제한 처리](resp-permission.html)를 따릅니다 |

- **목록의 개인정보는 마스킹 기준을 따릅니다**: 단계를 진행하는 시점은 고객 인증 전일 수 있으므로, 고객명 · 연락처 같은 값은 [마스킹 처리](resp-masking.html)의 기준으로 표시합니다.
- **오류가 나도 앞 단계의 입력은 지우지 않습니다**: 다시 시도할 때 조건을 처음부터 입력하지 않게 합니다.

#### 표시 방식

이 문서는 흐름만 정하고, 패널 안의 세부 구성은 업무에 맞게 정합니다.
업무별 구성은 와이어프레임 · 목업으로 따로 정리합니다.

- **단계는 사이드 패널 안의 아코디언으로 나눕니다**: 아코디언 한 칸이 한 단계입니다. 패널의 폭 · 헤더 · 푸터는 [사이드 패널](option-panel.html)을 따릅니다.
- **여러 개를 확정하면 조회조건 필드에는 요약해 표시합니다**: 고른 값을 필드에 모두 늘어놓지 않습니다. (예. 계약 3건)
- **업무세션에서 이어받은 고객은 잠금 표시와 함께 보여 줍니다 (가안)**: 조회조건 필드의 고객 값 앞에 잠금 아이콘을 두어, 이 화면에서 바꿀 수 없는 값임을 알립니다. 패널 안의 고객 단계도 고른 값만 보여 주고 펼치지 않습니다.

#### 실제 예시

화면을 열면 사이드 패널이 열리고, 회원목록 단계에는 업무세션의 고객이 고정되어 있습니다.
계약목록에서 계약을 고르면 패널이 닫히고 컨텐트를 불러옵니다.

고객만 정해져 있을 때 · 계약 선택부터새 탭에서 크게 보기※ 예시 이미지 — 레이아웃/디자인은 확정 아님. 패턴 구조만 참고.아래 두 예시는 업무세션에 정해진 값이 없을 때 패널에서 단계를 처음부터 고르는 흐름입니다.

조회조건 필드의 사이드 패널 아이콘을 누르면 ‘계약선택’ 패널이 열립니다.
전화번호를 입력하고 ‘검색’을 누른 뒤 고객과 계약을 차례로 고릅니다.

업무세션 없음 · 3단계 · 조건 입력 → 고객 선택 → 계약 선택새 탭에서 크게 보기※ 예시 이미지 — 레이아웃/디자인은 확정 아님. 패턴 구조만 참고.조회조건 필드의 사이드 패널 아이콘을 눌러 패널을 엽니다.
전화번호를 입력하고 ‘검색’을 누른 뒤 고객을 고릅니다.

업무세션 없음 · 2단계 · 조건 입력 → 고객 선택새 탭에서 크게 보기※ 예시 이미지 — 레이아웃/디자인은 확정 아님. 패턴 구조만 참고.
#### Do / Don't

###### Do · 이렇게 합니다

- 업무세션에 필요한 값이 모두 정해져 있으면 그 값으로 바로 컨텐트를 불러옵니다.
- 앞 단계까지만 정해져 있으면 그 값을 채운 채로 다음 단계부터 이어 갑니다.
- 단계가 몇 개든 조회조건에는 필드 하나만 두고 단계는 사이드 패널에서 진행합니다.
- 값을 바꾼 화면에서 Cross-linking으로 넘어가면 바뀐 값을 이어 줍니다.
- 업무에 필요한 단계까지만 거치게 합니다.
- 값을 바꾸면 앞 값의 결과를 지우고 다시 불러옵니다.

###### Don't · 이건 피합니다

- 값이 이미 정해져 있는데 사이드 패널부터 열지 않습니다.
- 업무세션에서 이어받은 고객을 업무 화면에서 바꾸게 하지 않습니다.
- 조회조건을 지정하지 않은 채로 업무 화면을 쓰게 하지 않습니다.
- 단계를 조회조건 모듈이나 본문에 펼치지 않습니다. (마지막 단계를 비교하며 골라야 하는 경우는 제외합니다)
- 앞 단계를 마치기 전에 다음 단계를 열지 않습니다.
- 선택을 중단했다고 기존 값을 지우지 않습니다.
